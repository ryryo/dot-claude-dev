# pstackの使い方を案内する

[Codexでの実行規則](../../execution.md)を読んでから使う。

質問には実装を始めず答える。作業の依頼なら `poteto-mode` へ進み、既存の許可範囲で実行する。説明するスキルを実際に読み、参照したファイルへ案内する。

未設定は `setup-pstack` と同梱の初回補助で診断する。7担当と現在利用できるモデル・思考量を確認し、既定は親を継承する。TOMLの配置と実担当の起動を区別する。導入だけでモデル上書き、定期実行、共通の常駐指示を作らない。

調査・構築・検証は `poteto-mode`、現コードと歴史は `how`・`why`、呼出と所有の設計は `architect`、隔離案の比較は `arena`、分担と競争は `swarm`、固定差分の反証は `interrogate`、外の影響は `blast-radius`、測定値は `benchmark-checklist`、反復誤りは `correct`、本人の規範は `automate-me`、指定メンテナーは `automate-maintainer`、中核担当は `automate-team`、再開は `recall` または `session-pickup`、PRを採用可能にする作業は `babysit`、許可された採用は `shipping` に案内する。

設計だけの依頼は設計で止める。PRの確認やレビューはマージ・受入権限を追加しない。起動だけでファイルは分離されず、書き手の作業場所が要る。検証不能は未確認である。将来の起動は明示依頼で対応する機能を使う。具体例を一つと参照先を示し、全体図を求められなければ短く答える。
