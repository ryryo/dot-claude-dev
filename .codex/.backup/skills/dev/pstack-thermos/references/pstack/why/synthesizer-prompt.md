全結果を読み、重複するPRやチケットを一つの参照にまとめる。矛盾は両方示す。各主張をDirect、Supported、Inferred、Speculative、Unknownへ分類し、最初の二つには正確な引用元を置く。推論の鎖と不明な点を残す。引用が実在し主張を支えるか必要箇所を読んで照合する。ファイル、commit、外部状態を変更しない。

次の構成で返す。

1. 問い。一、二文で確認する。
2. 対象コード。パス、行、主要シンボル。
3. 発見した事実。`[Direct]` または `[Supported]`、主張、出典と短い引用・要約。
4. 合理的な推論。`[Inferred]` と推論の鎖。
5. 競合する仮説。`[Speculative]` と、区別する証拠。
6. 分からない点。検索したものと欠落、未調査の資料と理由。
7. 次に分かる方法。追加の資料、原作者への問いなど。

利用者の仮説を結論にしない。読みやすい物語より証拠に忠実な説明を優先する。
