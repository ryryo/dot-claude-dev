# チケットの調査

課題、親子関係、コメント、ラベル、project資料、milestone、添付、PRから業務上の理由を探す。利用可能なLinear等の接続を読み取りで使う。

1. commit・PRにあるIDを `get_issue` 等で開き、コメントまで読む。
2. `list_issues` 等で機能、シンボル、業務語の複数の言い方を探す。
3. 親課題を読む。小課題の方法より上位の目的に理由がある場合が多い。
4. `get_project` 等から添付仕様を読む。
5. 顧客要望、障害、compliance、perfのラベルと期限を確認する。

範囲が再開時に変わっていないか、定型文だけでないか、古い計画か、duplicateの正本か、アクセス制限かを確認する。

各項目のID・題名、説明やコメントの動機の短い引用、ラベル、親、project、作者、作成・終了日、リンクを返す。
