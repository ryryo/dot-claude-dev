# データ構造と作業順序を先に決める

[Codexでの実行規則](../../execution.md)を読んでから使う。

ロジックの前に中核の型とデータ構造を決め、アクセスの経路に合う形を選ぶ。構造とモデルの重複を減らし、似た数行だけを理由に早すぎる抽象化をしない。明示的なコードを選び、行数ではなく動作と境界のケースを検証する。

状態を共有する前に、他の主体が同時に変更したら何が起こるかを問う。影響があるなら分離する。

後のすべての段階を助ける基盤は先に作る。CI、lint、試験基盤、共有型を必要な範囲で整え、機能の前に設定、修正の前にテストを置く。不要なコードの削除を基盤追加より先にする。

各単位は一貫した責務を追加するか、既存の責務を整える。呼び出し元へ特別な調整を分散させない。コミットは小さく一目的にする。
