# 呼び出し方と責務を設計する

[Codexでの実行規則](../../execution.md)を読んでから使う。

`how` と利用可能な依存関係の証拠で既存の経路を理解する。呼び出し元が望む使い方と、正しいデータの取得元・構造を先に書く。所有、寿命、並行処理、エラー、権限の境界を特定する。

選択が本当に開いている場合だけ、構造の異なる案を少なくとも二つ作り、インターフェースの深さ、状態の妥当性、検証しやすさで比較する。現在の要求を完全に満たす最小の案を選び、実装前に不足する実際の境界を証明するREDを定める。

[設計担当への指示](runner-prompt.md)、[判断理由](rationale-template.md)、[設計の問題候補](design-red-flags.md)を使う。

実装まで依頼されていなければ設計で止める。不要な互換層や将来向け設定を追加しない。呼び出し方、型とデータ、モジュール対応、却下案、選定理由、実際の経路の確認項目、検証計画を返す。
