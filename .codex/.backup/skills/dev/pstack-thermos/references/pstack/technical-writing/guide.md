# 技術文章を用途に合わせて書く

[Codexでの実行規則](../../execution.md)を読んでから使う。

疲れた開発者が一回で理解できる文章を目指す。不要な語を除き、短く日常的な語を選ぶ。規則が文章を悪くするなら別の直し方を選ぶ。実際の記号、ファイル、flag、commandを用い、造語で置き換えない。

文の長さを一律にせず、一つの主張とその条件・結果を自然に示す。二つの主張を無理に一文へ押し込まない。具体的に書き、説明文では比較の判断も示す。参照資料は事実に徹する。

## 文書の種類を選ぶ

Diátaxisの区分で、実行と学習はtutorial、実行と仕事はhow-to、理解と仕事はreference、理解と学習はexplanationとする。一文書に一つの主な用途を選び、異なる用途は分けてリンクする。

tutorialは読者が作るものを先に示し、各段階で観測できる結果を出す。説明は短くして別資料へ案内する。how-toは人の問題を解決する手順とし、必要な条件分岐は含めるが背景や網羅性のための説明を増やさない。referenceは事実・選択肢・制限・エラーを対象の構造に沿って記す。生成できる部分はコードから生成する。explanationは限定した「なぜ」に答え、設計判断・歴史・制約・代案を示す。

## 読者が動ける文にする

誰が何をするか明示し、事実は現在、将来は本当に今後の事項として書く。受動態は主体が不明か主題でない場合に使う。手順は具体的な動詞で書き、条件を操作の前、通常経路を例外の前に置く。

「簡単に」「すぐに」などで手順の難しさを決めつけない。不要な前置きや同じ文頭の連続を避ける。リンクは行き先の題名や内容を示す。「ここをクリック」だけにしない。見出しは行うことや伝える内容を示し、一つのH1と順序を保つ。順序には番号、並列には箇条書きを使い、項目の形を揃える。コードはコード書式、画面上の項目は必要に応じ太字にする。不完全な一覧はその範囲を先に示す。

## 一文の負担を減らす

STEから、一文に一つの操作または主張、条件・注意を対象の操作より前、同じ語は同じ意味、同じ操作は同じ名称という考えを使う。英語の目安は操作20語、説明25語だが、日本語の文字数へ機械的に変換しない。長い文でも必要な条件を削らず、文の意味の単位で分ける。冠詞や接続語を削って英語を曖昧にしない。

## 二通りに読める文を直す

Global Englishから、否定・限定を対象へ近づけ、長い名詞の連鎖をほどき、指示語の対象を一つにする。同じものの名称を統一する。並列や条件の関係が曖昧なら文を分ける。動詞と文の関係を示す語を省かない。余分なセミコロン・長いダッシュ・括弧・スラッシュ・略語・慣用句・比喩を整理する。ただし識別子・設定キーは保持する。

語数を減らすために内容や条件を落とさない。変わっていない文を言い換えるだけの差分を増やさない。読者が機能を理解できる名称にし、新しい抽象的な言い回しを見つけたら `unslop` への提案と差分を報告する。そのスキルを無断で編集しない。

他言語の文体規則を日本語へ適用するときは、構文や単語数を機械的に転写しない。主体、意味、条件、操作順が読み取れるかで判断する。
