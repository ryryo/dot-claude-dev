# 確認できる単位を順に進める

[Codexでの実行規則](../../execution.md)を読んでから使う。

作業を、毎回検証できる小さな単位へ順序づける。正常な基準、単一の変更、検査の実行を一組にし、現在の単位が合格してから次へ進む。許可された作業では正常な最新の基準へ合わせ、現実の差分で測る。

道具で一括処理できても、単位ごとの検査を省略しない。まとめてから失敗を探すと、原因が埋もれ、失敗した基準へ後の作業が積まれる。

レビューする人が再現できる順序でコミット・PRを積む。失敗するテストから修正、削除から再構成、基準測定から変更、基盤から機能など、順序が成果の説明になる形を選ぶ。`principle-prove-it-works` と `principle-build-the-lever` を併用する。
