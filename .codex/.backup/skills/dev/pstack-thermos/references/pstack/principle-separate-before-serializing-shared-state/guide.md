# 共有する前に状態を分ける

[Codexでの実行規則](../../execution.md)を読んでから使う。

まず、複数の主体が同じ変更可能な対象を持つ必要があるかを確認する。独立した事実を出すだけなら、専有するファイル、キー、ブランチ、状態ディレクトリへ分け、読む段階や報告時に統合する。

一つの `state.json` で各担当が自分の項目だけを書く方法も共有変更である。別ファイルへ分けるほうが共有を除ける。

同じ対象への書込みが本当の不変条件なら、ロック、直列段階、単一書き手、原子的な比較交換で制御する。指示文や慣習だけを並行処理の制御としない。「ロックが必要」を既定の答えにせず、設計の確認点とする。
