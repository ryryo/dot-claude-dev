# 繰り返す誤りを構造で防ぐ

[Codexでの実行規則](../../execution.md)を読んでから使う。

最近のコミット、撤回、レビュー、指示、回避策のコメントを読み、2回以上発生した誤りを種類に分ける。次の担当が近い例だけを読んでも全体に正しい変更になる構造を考える。

まず状態の所有と対応する経路を一つにし、不正なimportや同期する別一覧をなくし、古い例を削除する。次に不正状態が型で書けないようにする。まだコンパイルできるなら、正しいファイル・型・関数を示すlintやCIを追加する。既に多い傾向は追加分から止める方法を選ぶ。動作をテストし、呼ぶ関数が何も返さなくても通る検査は直すか除く。文章の規則は判断だけが残る場合に最後に書く。

多い種類から一つずつ修正し、新しい検査が実際の過去の誤りで失敗することを示す。同じコマンドをローカルとCIで使う。例外には対象行の理由・期限・人の承認を付ける。

指示資料に規則と強制する仕組みの対応を保持する。既存規則の再違反で強制がなければ同じ変更で仕組みを直す。起こり得なくなった規則は除く。種類、根拠、選んだ層、より強い層で解決できない理由を返す。
