# 測定値の意味を確かめる

[Codexでの実行規則](../../execution.md)を読んでから使う。

測定値はシステムについての主張である。信頼・報告・判断の前に制限要因を調べ、意図した処理以外を測っていないことを確認する。

「なぜ2倍にならないか」を説明できる資源や経路を特定する。CPU、ロック、ディスク、通信、負荷生成側をプロファイルや実行中の計数から確かめてコードへ対応させる。コードを読んだ推測だけでは制限要因の証拠にならない。

失敗した要求、キャッシュや省略された処理、片側だけ未調整の設定、実行ごとの雑音、全体に影響しない部分測定を候補に挙げ、一つずつ証拠で除く。回数、ばらつき、制限要因を数値と一緒に残す。短縮量が変更箇所の元の時間より大きい場合は測定を疑う。

性能値には `benchmark-checklist` を使う。評価値も、全試行が課題を実施したか、複数試行・モデルで差が維持されるか、実際の用途に関係するかを確かめる。出力の実在を確認する `principle-prove-it-works` と、数値の意味の確認は区別する。
