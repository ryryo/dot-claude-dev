# 差分の外にある影響を確かめる

[Codexでの実行規則](../../execution.md)を読んでから使う。

`how` は動作、`why` は理由、この手順は他の箇所の破損を調べる。呼び出し元一覧や説得的な文章だけで終えず、安全性が依存する一つか二つの事実を実際のコードで証明する。

証拠を、自己申告、正確なコード行、失敗経路が到達しない確認、実コードを実行する検査、実アプリの再現の順に可能な範囲で進め、どこまで確認したか示す。

差分と追加・変更・削除した記号を読み、`why` で関連PRとコミットを取得する。安全と言える中心の事実を探す。呼ぶライブラリの固定版とローカル修正、microtask、unmount、終了処理、フレームワークの差を読む。JSON、DB列、通信形式、他言語の読取、機能フラグ、複数段先の処理など、記号検索だけで見えない経路を追う。

確認できた危険には失敗の仕方、ファイルと行、起こりやすさと費用、検証方法を付ける。確認して除外した危険は別に示す。架空の呼び出し元やAPIを作らない。中心の事実を実コードに呼び出すスクリプトやテストで検証する。大きい変更は許可された `arena` で独立に検討する。

変更内容、中心の事実と証拠段階、確認できた危険、除外した危険、採用前の最小の再現・検査を返す。証明できなければ未検証と記す。`unslop` で整え、公開前に私的情報を除く。
