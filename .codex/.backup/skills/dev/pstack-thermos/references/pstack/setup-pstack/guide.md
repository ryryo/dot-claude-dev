# pstackの設定

[Codexでの実行規則](../../execution.md)を読む。Codexの専用担当を設定し、Cursorのルールや架空のモデル名を作らない。

## 初回配置

[初回補助](../../setup.md)に従い、対象の絶対パスを指定して `python3 <skill-root>/scripts/setup.py check --project <project>` で診断する。未設定なら許可された対象へ `install` を実行する。競合する設定は上書きしない。

## 担当の調整と実行確認

1. 対象リポジトリの正確な絶対パスについて信頼を確認する。未信頼のプロジェクトの `.codex/` 設定は読み込まれない。Codexの画面、または利用者の設定の `[projects]` と `trust_level = "trusted"` で信頼を設定してもらう。勝手に信頼を追加しない。
2. 対象の `.codex/agents/` と `.codex/config.toml` を読む。個人設定の依頼がある場合だけユーザー共通の設定も対象にする。
3. Codexが今提供しているモデルと対応する思考量を列挙する。その一覧を設定の根拠とする。
4. 7担当（`poteto-agent`、`comment-sicko`、`pstack_skeptic`、`pstack_architect`、`pstack_minimalist`、`thermos_correctness`、`thermos_quality`）の現在のモデル・思考量・サンドボックスを示す。
5. 既定では親のモデルと思考量を継承する。利用者が固定の担当割当を依頼し、組合せが対応している場合だけ明示値を追加する。
6. レビュー担当は読み取り専用にする。担当設定で親の権限や確認の境界を弱めない。
7. 各TOMLを検査し、新しいチャットで7担当を実際に起動する。[初回補助](../../setup.md)の確認方法、または `python3 <skill-root>/scripts/maintenance/smoke_agents.py --repo <project>` を使う。全担当が検出・起動できるまで「実行確認まで完了」と報告しない。ファイルの配置完了とは区別する。

共通の既定値はCodex設定の対応する `[agents]` キー、担当固有の動作は独立した `.codex/agents/<agent>.toml` に置く。別のモデル対応表やCursorルールを作らず、モデルを黙って置き換えない。

実際の利用画面を検証する仕組みがない場合は、任意の次の作業として `create-verification-skill` を案内する。

## 利用者が思考量の予算を指定した場合

無制限・大・中・小を示す。後の3つは、実際に対応する思考量の上限をそれぞれ `xhigh`・`high`・`medium` とする。無制限は上限を外す意味であり、モデルが持たない `max` を作らない。予算のために継承モデルや継承思考量を変更しない。

上限を適用する前に、利用者が選んだ上限適用前の値をプロジェクトのpstack設定メモへ保存する。再実行ではその値から計算し、意図的な担当別の指定を維持して変更案を示す。既に制限した値を再度制限せず、元の希望を推測しない。無制限へ戻す場合は、対応する元の値へ復元する。明示するモデル・思考量の組合せを現在の環境の情報で検証してから、対応するTOMLキーへ書く。
