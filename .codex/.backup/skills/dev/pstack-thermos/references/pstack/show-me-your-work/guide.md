# 判断と証拠を記録する

[Codexでの実行規則](../../execution.md)を読んでから使う。

正しい記録を一つにする。[TSVひな型](decision-log-template.tsv)の列名を保持し、各判断を一行、各セルを一行にする。

`ts` はISO8601、`phase` は段階、`decision` は選択または実施内容、`why` は平易な理由、`evidence` はコミット・PR・ファイル行・成果物・トレース・画像の所在、`result` は実際の結果か条件の状態とする。証拠欄へ説明段落を入れない。

```sh
<skill-root>/scripts/pstack/show-me-your-work/log.sh <logfile> <phase> <decision> <why> <evidence> <result>
```

補助は時刻と初回のヘッダーを付け、タブ・改行を整え、`=`・`+`・`-`・`@` で始まるセルへ引用符を付ける。手で追記する場合も同じ処理を行う。

毎操作でなく、分岐の選択、検証付きの単位完了、方針変更・撤回と原因、不足、検査の修正をその時点で記録する。反復実行は一反復に一行。自明な作業は省く。

一実行は一チャットと後のターン・要約を含む。引継ぎ、別担当、新チャットは新しい実行になる。既存ログへの最初の追記と、他実行の `start` 後に戻った最初の追記は `phase=start` にする。戻ったら末尾を読み、他実行が書いたか確認する。`start` には自分が書いていない直前の時刻範囲と、証拠欄へ実行のIDを記す。他用途に `start` を使わない。

既定は作業場所の `decisions.tsv`、複数作業は `.audit/<task-slug>.tsv` に置きGitへ入れない。後から成果を検収するため必要な大きい作業では保存対象にする。追記専用とし、誤判断も行を編集・削除せず訂正行で置き換える。

終了時に自分の `start` から次の別実行の `start` までの範囲を、現在の会話、ツールの記録、利用可能な実行限定のTraceDecay証拠と照合する。他プロジェクトや非公開の履歴を走査しない。履歴を取得できなければ不足を示す。各行に実際の判断・行為と解決できる証拠があるか、方針変更や却下の抜けがないか確認する。架空の行も削除せず、実際の事実と根拠を示す訂正行を追加する。自分の範囲外は監査しないが、自分の作業から誤りが判明した行は訂正する。

回収前に、許可された独立担当へ記録と実行限定の証拠を渡し、弱い証拠、未実施の検証、範囲拡大や症状対処、見落とす不足を調べてもらう。別モデル系列は実際に対応していて指定される場合だけ使う。自己確認を独立レビューと呼ばない。できなければ未実施と示す。

記録を作った作業の報告には注意点を添え、`reviewed by <model>` と確認した担当のモデル、該当行への指摘を示す。指摘なしは有効な結果だがモデル名だけを結果にしない。レビュー未実施なら架空の名前や合格を作らない。

読むときは上から根拠をたどる。端末では `column -s$'\t' -t decisions.tsv` を使える。他のスキルはこの記録形式を参照し、別の形式を作らない。
