# 使う人の体験から決める

[Codexでの実行規則](../../execution.md)を読んでから使う。

実装の都合と利用体験が食い違う場合は、使う人の体験を優先する。機能・操作・選択肢の必要性を示す。未完成の多数の機能より、少数でも使いやすい機能を提供する。

設計判断は本実装の前に試作する。遷移、整列、余白、フィードバック、エラー状態を整える。機能は中心となる作業を助けるか、邪魔にならない形にする。

利用者には画面を使う人、ライブラリや内部APIを呼ぶ同僚、次に保守する開発者を含む。それぞれの立場から影響を説明する。基盤は体験のために整える。`principle-foundational-thinking` は順序、この原則は目標を決める。
