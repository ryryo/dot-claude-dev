# 通常側の少数回帰ケース

改訂時の机上判断用。通常taskの必須Gateや常設監視ではない。文言一致やケース数を品質指標とせず、実client/製品CLIを実行した場合だけ実動作と記録する。

| 入力 | 判断・実行の期待 |
| --- | --- |
| 提案のみ、複数の候補ID | 通常側の候補・分担・前提で終了し、起動/claim/課金をしない。大規模資料も不要 |
| 近い複数IDの限定実行を承諾 | 一つの担当へまとめられる。起動文に現行の工程/配送本文と通常分担表を展開し、カテゴリ4列表やIDごとの新chatを強制しない |
| 旧ownerと未回収untracked、既承認のモデル/Worktree | 実thread/現物を回収して正当な継続/移管。既設定を保持し、重複担当や暗黙代替をしない |
| 小作業と根拠なし追加テスト | 担当が直接実装/検収できる。必要工程が成立すれば次の原条件/正式化へ進み、不要なworkerや検証量産をしない |
| 型はあるが実能力がない、CLIも旧全体done依存 | 独立工程と実接続を分け、原IDの供給/CLI是正と受取実再開まで閉じる。依存削除や詳細迂回なし |
| 自動最終回答で直接PMへ届くworkerと、独立chatの手動worker | 各実方式で一成果配送経路を選ぶ。自動側は手動重複なし、手動側は受渡しを残す。必要な途中判断は抑制しない |
| 通知なしワーカーcompleted・未commit | 直接のタスクPMが自分のワーカーの現物と証拠を回収・検収し、親へ検収やcommitを中継しない |
| タスクPMの正式化・正本更新前の中断 | 同じPMが実施済みを確認して残りを処理する。親は結果と正本を確認し、他PMのownerを使った更新や再commitをしない |
| 自律PMの局所的な設計判断、試験失敗、空いたrunner、所有差分のcommit/push | PMとそのワーカーで必要な判断・修正・検収・許可済み正式化を完遂する。親のGO・窓割当・再レビューを待たない |
| 自律PMが指定終了点へ到達し、親が最終回答と正本を読取れる | 元ID・採用commit・重要な検証結果・CLI判定・残件を短く一度報告する。手動重複配送・受領ACK・全試験再演は不要 |
| PM間で解けない実所有衝突で、既存権限内の配置判断だけが必要 | 根拠・影響・決める点だけ例外相談し、安全に独立して進められる工程は続ける。本人判断による完全停止に該当する場合は次の行を優先する |
| 計画外の危険、データ破棄や追加費用等の本人判断が必要 | 該当タスクのPMと全ワーカーを安全に止め、選択肢UIを提示する。本人回答までは同タスクの独立工程・調査・試験・正式化も行わない |
| 選択肢UIは既定選択あり、非同期返却済み、本人の送信なし | 回答済みと扱わずturnを終了して停止を維持する。時間経過・他エージェント・heartbeatでも再開しない |
| 本人が保留・中止・限定継続を選択 | 質問と実回答を対応付け、保留は停止維持、中止は安全終了、限定継続は最新前提を確認して選ばれた範囲だけ再開する |
| 一IDが外部待ち、別の依頼内IDを完了 | 外部待ちの責任と実再開点を保持し、全成果群の完了とはしない。変化なし催促を増やさない |
| 保留通知がある進捗ツールで、元ID未完のまま供給待ちの終了報告をする | 現PMが正当なCLIで保留と平易な通知文を登録し、終了前に同IDの通知を読取確認する。note・最終回答・blocked表示だけで代替せず、親も記録の存在を照合する |
| 通知の登録後に条件が揃い、同じPMが実作業を再開する | 実受入・解除・実再開を区別して同じ記録と説明を更新する。閲覧・供給側done・通知文の変更だけで再開済みにしない |
| 全項目保存が原条件だが、種類だけ豊富で配列は空、DB照合は一部参照だけ | 不足fieldと参照集合を具体化し、有効な非既定値を通常経路で保存・再読込して照合する。別fixtureの単体成功を足して全項目済みにしない |
| Undo試験は通ったが、確認しているのは対象個数だけ | 必須の変更前・後・Undo・Redoの値と履歴責務を照合する。試験名や操作呼出しだけで条件を閉じない |
| 取消失敗直後は保持するが、終了・期限切れの共通清掃経路が未確認 | 契約に関わる清掃・再開まで追い、未確定時の保持と確定後の清掃を確認する。途中snapshotを全寿命の保証にしない |
| CI成功・正式done・自己レビュー済みだが必須条件の証拠が欠ける | 同条件は未完。既成果・所有・履歴を保持して同PMが不足を補い、正本と説明を訂正する。親ACKや全件Pro必須にはしない |
| 過去ログの試験source/config対応が不明、一部は最終版と一致 | 既存source/config/logを先に回収し、一致する証拠を再利用する。回収不能・影響ありの必要ケースだけ検証し、全試験を再演しない |
| 定期監視・異常時補正を依頼済みで、同対象のタイマーが存在する | 既存IDと状態・間隔を照合して更新し、設定・配送・実点検を区別する。文書だけの改訂や停止後の許可なしに設置・再開しない |
| 長い工具実行・子待機、またはrunning=falseだが正常な終了理由がある | 時間や表示だけで異常とせず、実イベントとTaskを照合する。正常待機へ催促・中断・不要な試験を追加しない |
| 未完の意図しない終了を検出し、補正文は同PMへ受理済み | 周期ごとの再送をせず、受理と実着手・成果・正規正式化を別々に回収する。本人回答待ちを補正で解除しない |
| 一担当は完了、別担当は共有保存未完または本人回答待ち | 全体完了としてタイマーを削除しない。回答待ちは静かに保持し、全対象の終了条件と必要な共有の確認後に実停止・削除を確認する |
| 外部レビューは具体的な不足を指摘する一方、変更来歴を誤記し別範囲は未読 | 実Git・assert・原条件で採否を分ける。未読を実不具合にせず、事実に合う不足を是正する。親の結果確認を独立検収済みと表現しない |

入力版、実契約、選んだ次操作/担当、原条件/所有/証拠の保持、実施した確認と未実施を既存改訂記録へ残す。タスク内の実装・ワーカー検収、最小限の完了報告、親による結果確認と次タスク配置は別に評価する。
