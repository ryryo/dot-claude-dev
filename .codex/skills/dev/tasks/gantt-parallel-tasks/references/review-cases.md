# 通常側の少数回帰ケース

改訂時の机上判断用。通常taskの必須Gateや常設監視ではない。文言一致やケース数を品質指標とせず、実client/製品CLIを実行した場合だけ実動作と記録する。

| 入力 | 判断・実行の期待 |
| --- | --- |
| 提案のみ、複数の候補ID | 通常側の候補・分担・前提で終了し、起動/claim/課金をしない。大規模資料も不要 |
| 近い複数IDの限定実行を承諾 | 一つの担当へまとめられる。起動文に現行の工程/配送本文と通常分担表を展開し、カテゴリ4列表やIDごとの新chatを強制しない |
| 旧ownerと未回収untracked、既承認のモデル/Worktree | 実thread/現物を回収して正当な継続/移管。既設定を保持し、重複担当や暗黙代替をしない |
| 小作業と根拠なし追加テスト | 担当が直接実装/検収できる。必要工程が成立すれば次の原条件/正式化へ進み、不要なworkerや検証量産をしない |
| 型はあるが実能力がない、CLIも旧全体done依存 | 独立工程と実接続を分け、原IDの供給/CLI是正と受取実再開まで閉じる。依存削除や詳細迂回なし |
| 自動最終回答で直接PMへ届くworkerと、独立chatの手動worker | 各実方式で一成果配送経路を選ぶ。自動側は手動重複なし、手動側は受渡しを残す。必要な途中判断は抑制しない |
| 通知なしcompleted・未commit、正本更新前の中断 | 親が現物と処理済み工程を確認して残りを正式化し、同じ成果を再commitしない |
| 一IDが外部待ち、別の依頼内IDを完了 | 外部待ちの責任と実再開点を保持し、全成果群の完了とはしない。変化なし催促を増やさない |

入力版、実契約、選んだ次操作/担当、原条件/所有/証拠の保持、実施した確認と未実施を既存改訂記録へ残す。実装品質、配送、親の実再開は別に評価する。
