# 限定タスクの起動と担当の実行

通常の承諾された限定成果群を担当chatへ渡す入口。複数IDをまとめてよい。大規模PMには別の[単体ID入口](../../gantt-development-orchestrator/references/playing-manager.md)を渡し、本書の複数ID継続を混ぜない。通常担当が大規模手順を読み込む必要はない。

## 起動文

最新owner・依存・既成果を読み、[共通実行条件](../../codex-task-split/references/execution-context.md)で実起動設定/許可、[共通配送](../../codex-task-split/references/delivery.md)で直接の担当と一経路を確認する。以下へ実入力を埋め、markerを対応する正本から展開する。

`{{TASK_TABLE}}`は[通常側の分担表](../SKILL.md#4-利用者へ示す)、`{{EXECUTION_LOOP}}`は[工程本文](../../codex-task-split/references/execution-loop.md#起動文へ展開する工程本文)、`{{DELIVERY}}`は[配送本文](../../codex-task-split/references/delivery.md#起動文へ展開する配送本文)を使う。表の具体的分担は担当自身が示す。これは文面の組立てであり、実clientのAPIではない。

```text
役割: 今回承諾された限定成果群を持つ作業担当
原依頼/対象ID/原条件: <実在参照、body/check/必要level、複数IDならその承諾範囲>
残条件/最初の成果: <既充足と証拠、今回減らす条件と必要成果>
前提/境界: <供給/consumer版・必要能力・解除条件、owned/共有操作、既成果/WIP/未回収>
正本/実CLI: <唯一の正本、最新revision/ownerの確認、正当な開始/完了/移管手順>
実設定/環境: <project/host、認可済みモデル/推論・起動方式/開始元・cwdとsetup>
許可/必要宛先: <実利用者指示、直接の指示元の正式ID/host、通信/委任/commit等の許可範囲>
配送/再開: <確認済みの一成果配送経路と根拠、必要相談と実再開方式・不足>
現行契約: <本書、共通実行条件・実行ループ・配送と必要仕様の確認済み参照>

最初に原依頼・実作業先・差分・正本・ownerを確認してください。移管前の読取だけなら編集/claimを開始しません。
実装/worker起動前に自chatで「開始：対象ID」と次の分担表を提示してください。
{{TASK_TABLE}}
自分の中核実装、必要なworker成果または不使用理由、実モデル/推論と理由、前提/順序・検収と工程終了条件を具体化します。
実着手で正当なCLI更新を行い、指示元のACK待ちなしで進めます。既に合意した完全な表は対象IDと現在の変更点を照合して再利用できます。

{{EXECUTION_LOOP}}

中核判断・統合・worker回収・自己検収・正当なCLI完了と必要正式化を自分で持ってください。
必要なowned成果だけcodex-task-splitへ委任し、通知なしcompleted/未commit成果も回収します。
原条件が残れば承諾された成果群の中で続け、阻害したIDへの実復帰を確認せずに依頼終了としません。
未実施の必須サービス/OS条件を保ち、部品・main反映・worker終了で依頼全体を完了にしません。
全依頼の原条件と必要正式化を閉じたら成果版・証拠・原条件の結果・未完有無を直接の指示元へ渡して終了します。無関係な成果群へ拡張しません。

{{DELIVERY}}
```

実送信前にmarker・仮値の残存と本文/実引数の許可・宛先・モデル/方式を確認する。結果不明は照会して重複作成せず、正式ID/cwd/HEADと担当chatの実際の開始表・CLI実着手を確認する。契約配送や読了を実行確認にせず、通常着手をACK待ちにしない。大規模側のカテゴリ4列表・元ID別新規chatを通常側へ追加しない。

## 担当の実行

開始/再開で原条件、所有、実前提/設定、既成果/未回収を照合する。同ID・同分担の継続は完全な既存表と差分を使い、別IDの開始や分担変更では現在の対象と分担を示す。旧編集の終了と正当な移管前に同範囲を編集しない。

[codex-task-split](../../codex-task-split/SKILL.md)で限定成果だけ委任し、[回収契約](../../codex-task-split/references/main-review.md)で未回収の実状態・採否・修正/引取りを扱う。scopeの選定・開始/終了は本書で決め、共通側から担当範囲を拡張しない。

供給不足・CLI拒否・未担当・根拠なし反復は共通実行ループで解決担当と次操作を定め、実成果の受入と阻害した元IDの実工程まで追う。是正文の配送で終了せず、非依存工程は進める。元check/必要levelを満たす範囲だけCLI完了にし、残る承諾済みIDとCLI/commit/受渡しを閉じる。

## 連絡

workerの成果/判断待ちは直接の担当へ。許可された担当間の共有操作・供給の調整は必要な時だけ行い、毎回上位承認を挟まない。未決のscope/契約/権限、担当間で解けない衝突は実際の指示元と既存の判断経路へ戻す。

局所試験・修正・待機の全経過を転送せず、具体的な判断/操作/成果受渡しと限定依頼完了に必要なものを一経路で送る。配送結果不明はdeliveryで処理し、受領ACKだけで相互再起動しない。
