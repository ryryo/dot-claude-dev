# 限定タスクの起動と担当の実行

起動する側は最新owner・依存・既成果を照合し、[共通実行条件](../../codex-task-split/references/execution-context.md)の許可・実ツール・設定で作業担当を起動する。通常モードでは今回承諾された限定成果群を渡し、複数IDを含めてよい。共通規則を起動文へ全文コピーしない。

大規模モードから担当の実行・回収責任を再利用する場合は、[単体ID PM契約](../../gantt-development-orchestrator/references/playing-manager.md)が担当範囲・開始・継続・終了を定める。起動には[大規模の起動手順](../../gantt-development-orchestrator/references/task-launch.md)を使い、本書の複数ID継続を持ち込まない。通常側にはこの制限を適用しない。

## 起動文

```text
役割: 今回の限定成果を持つ作業担当
原依頼・対象ID・到達点: <実在参照と今回の範囲>
元check・必要level: <既存参照>
順序・必要能力: <供給版/受入範囲/解除条件、後続へ残す仕事>
編集・実行境界: <中核実装/専有範囲/共有担当/環境手順>
正本・CLI: <確認済み絶対パス・利用方法>
既存成果: <固定版、未受入、未回収への参照>
担当・worker設定: <既合意モデル/推論、委任対象と認可>
起動条件: <project、local/明示Worktree、承認済み開始元>
通信・正式化: <指揮者の実ID/host、実際の許可、commit方針>
回収・再開: <実際に使う方式と未確認部分>
担当入口: <本資料の確認済み絶対パス>
開始時の出力: 実装・worker起動前に、担当入口の「担当の実行」に従って、自分のchatへ対象IDと分担表を提示する。承認済み範囲は提示後に進め、指揮者のACKを待たない。
```

共通の起動確認で正式ID/cwd/HEADを対応付ける。利用者に成功分と保留/失敗を分けて示し、同じ成果を重複起動しない。許可された協調で受渡しに必要な場合だけ相手の正式IDを伝える。

指揮者は担当chatの実際の開始提示を下記手順と照合する。契約参照の送付や「読んだ」という報告だけで提示済みとせず、不足する提示・分担を補わせる。適正な着手を指揮者のACK待ちにしない。

## 担当の実行

1. 原依頼・実作業先・差分・正本・ownerを確認する。実装・worker起動前に、担当chatで「開始：対象ID」と[分担表](../SKILL.md#4-利用者へ示す)を提示する。自分の作業、worker成果または不使用理由、モデル・推論と選定理由、順序・検収方法を示す。既に合意した表を引き継ぐ場合は対象IDと変更点を示せばよい。別IDの開始・分担変更時も提示し、同ID・同分担の継続は変更点だけを補う。実着手でclaim/in_progressを更新し、移管が必要なら旧担当の編集終了と引継ぎを確認する。
2. 自分の中核実装・統合を持ち、[codex-task-split](../../codex-task-split/SKILL.md)で必要なowned成果だけ委任する。worker宛先は自分の実ID。実装委任と調査、実起動と発言を区別する。
3. 独立作業を進め、待機前・再開時は[回収・検収契約](../../codex-task-split/references/main-review.md)で実状態を確認する。未commit成果を回収して、局所修正・引取りを自分で処理する。
4. 元check・必要levelと適用Gateを満たす範囲だけCLIで完了にする。部品・接続・検証・未実施を分け、残る依頼内IDへ進む。限定成果群の外へ自律拡張しない。
5. 共通実行条件の正式化に従い、許可済みcommit・引渡しを行う。失敗した工程は次の対応を残す。検収済みcode、正本、commit、配送の途中状態を同じ成功で括らない。

報告は実在ID、成果/採用版、原checkの充足と残件、検証結果/環境、正本更新、repo別commit・push有無、次の対応を短く示す。元依頼に必須の実サービス・OS等が未証明なら未完のまま残す。

## 連絡

workerの成果・判断待ちは直接の担当へ。許可された担当間の共有境界と供給は直接調整でき、毎回Rootの再承認を挟まない。担当内の試験・局所修正・通常の待機は既存記録へ残す。

指揮者へは必要な統合成果、担当内で解けない衝突、scope/契約/権限を変える判断、限定担当全体の終了を送る。判断依頼には根拠・影響・推奨案・決める点を付ける。送信不明と未着は共通配送契約で処理し、受領ACKだけで相互再起動しない。
