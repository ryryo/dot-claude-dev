# GitHub相談と成果作成の依頼文

必要なテンプレートだけを使い、括弧内を実在する情報へ置き換える。既に合意した内容を再び未決に戻さず、許可された工程を明記する。

## 1. GitHubコードを読んで方針を相談する

```text
GitHub接続から（owner/repository）の（ブランチ、確認commit）を読んで相談に乗ってください。
目的は（解決したい問題・できるようにしたいこと）です。
入口になるコード・仕様は（リポジトリ内のパス・シンボル）です。必要な呼出元や関連契約も確認してください。
維持する動作・制約は（合意済み事項）、対象外は（範囲）です。
現在分かっていることは（症状・既存案・確認済みの証拠）、未確定は（事項）です。
手元だけにある変更・ログは（未収録の内容、または該当なし）で、GitHubに反映済みとは扱わないでください。

今回は（相談だけ／軽微修正はブランチ・PR、他はIssue化／Issue化まで）の依頼です。
まず関連コードを読み、確認した参照版・パスと、事実・提案・未確認を分けて示してください。
推奨方針、維持する動作、変更範囲、受入条件、必要な検証を整理してください。
利用者が選ぶ必要のある事項は、選択肢と影響を示し、合意前に決定済みにしないでください。

文言・説明・誤記など、変更が明確で実行検証をほぼ必要としないものは軽微修正の候補です。
動作を変えるものや実行検証が必要なものは、Codex向けIssueの候補として整理してください。
ローカル再現が中心なら、原因を推測で確定せず、既知の事実・再現条件・調査対象をまとめてください。
相談だけの依頼では、GitHubの書き込みを行わないでください。
```

## 2. 合意事項を反映して改訂する

```text
同じ相談を、次の確定事項に合わせて更新してください。
利用者と合意した内容：（決定事項と維持する動作）
コードとの照合で訂正する点：（主張・対象版の根拠・訂正内容）
未決のまま残す点：（未選択・未確認）
今回許可された工程：（相談／軽微修正のPR／Issue作成・更新）

関連する変更案・受入条件・検証方法を整合させてください。
確定事項を最初から作り直さず、今回必要な変更だけを反映してください。
```

## 3. 軽微修正を専用ブランチ・PRへ残す

```text
合意済みの軽微修正として、（owner/repository）の（baseブランチ、確認commit）を基点に進めてください。
変更対象は（パスと変更前後の内容）、編集範囲は（範囲）です。
維持する動作・対象外は（事項）です。
専用ブランチは（codex/で始まる作業名）、既存の同作業のPRは（URL、またはなし）です。

許可された範囲だけ修正し、専用ブランチへコミットしてPRを作成・更新してください。
baseブランチへの直接コミットとmergeは行わないでください。
実行検証や範囲拡大が必要と判明したら、その理由と残件を示し、Issue向けに整理してください。
書き込み機能が使えない場合は、対象版に対応する確定した差分を本文で返してください。

結果にはPR URL、base/head、修正commit、実際の差分、実行した検証・未実施、残件を示してください。
提案だけの検証を成功したと書かないでください。
```

## 4. Codex向けIssueを作成・更新する

```text
（owner/repository）の（関連する既存Issue URL、または新規）に、合意した内容を整理してください。
リポジトリのIssueテンプレートがあれば、その構成を使ってください。
対象コードの確認基点は（ブランチ、commit）、参照したコードは（パス・シンボル）です。
確定事項は（内容）、未決事項は（内容）、公開範囲の条件は（適用先の規則）です。

本文には次を含めてください。
- 目的・期待する利用動作、問題なら症状・期待と実際・再現条件
- 合意した方針と判断根拠、関連コードと確認基点
- 変更範囲と対象外、維持する動作
- 受入条件と検証方法、実施済みの証拠と未実施
- 未決事項と、実装または調査・設計として次に進める内容

会話リンクは補足にし、Issue本文だけで担当者が依頼内容を理解できるようにしてください。
未合意の仕様を決定済みにせず、必要なら調査・設計のIssueとして到達点を定めてください。
同じ作業の既存Issueがあれば更新し、重複作成しないでください。
指定されていないassignee・label・milestoneは追加しないでください。
今回の依頼はIssue化までであり、Codexタスクの起動は行わないでください。
書き込み機能が使えない場合は、確定したタイトルと本文を返してください。
作成・更新した場合は、実際のIssue URLと内容を示してください。
```

実装までの開始指示が既にある場合も、Issueを確認してからCodexが引き継ぐ。Proへの依頼文にCodexチャットの起動を委ねない。
