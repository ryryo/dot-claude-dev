# 大規模ガントのカテゴリ別運営

体制は「カテゴリオーケストラ→元ID一つごとの新規chatのPM→限定ワーカー」とする。カテゴリは多数IDを管理し、PMは一つの元IDを完了まで担当する。常設の全体オーケストラや全成果の承認上位は置かない。

限定された成果群をまとめて分担する依頼は[gantt-parallel-tasks](../gantt-parallel-tasks/SKILL.md)を使う。通常担当は複数IDを扱える。作業数やWorktree数だけで大規模モードへ切り替えない。

計画相談なら計画までにとどめる。実行は利用者が許可した範囲で行い、モデル・推論・環境・操作権限はprojectの規則と[共通実行条件](../codex-task-split/references/execution-context.md)から引き継ぐ。スキルを読んだことを、新規起動・通信・移管・Worktree・課金・タイマー設置の許可にしない。

## 役割と読む資料

| 担当・場面 | 責任と入口 |
| --- | --- |
| カテゴリの通常管理 | 本書で全管理ID、配置、供給待ち、未回収を確認する。起動時は[起動手順と送信文](references/task-launch.md)を使う。 |
| 単体ID PM | [PMの実行入口](references/playing-manager.md)から設計・実装・自己検収・完了処理を進める。カテゴリの起動資料一式は読ませない。 |
| 供給不足・CLI拒否・完了条件の確認 | [scopeと開始・完了判定](references/scope-and-gates.md)。共有仕様や担当を変える場合は[カテゴリ間調整](references/category-coordination.md)も読む。 |
| 停滞・反復・状況照会 | [カテゴリ内点検](references/execution-review.md)。解消すべき問題を絞り、必要な復旧手順へ進む。 |
| 承認された担当交代・統合集約 | [所有移管](references/consolidation.md)。通常の起動や部分供給には要求しない。 |
| スキルの改訂 | [回帰確認](references/review-cases.md)。各製品作業の追加Gateにはしない。 |

ワーカーの指示・回収・採否は直接のPMが担当する。カテゴリはPMの中核実装や最終検収を重ねず、ワーカーへ並行して指示しない。設計・最終採否・検収を名目上ワーカーへ移し、役割別のモデル指定を回避しない。

## 全管理IDから配置する

原依頼、実際の起動依頼、承認された追加・移管を唯一の進捗正本と双方向に照合する。カテゴリの管理範囲を合わせて全原scopeを覆い、未割当や重複を元IDのまま解消する。旧owner、待機中、未担当も対象に含め、owner検索やready一覧だけで分母を作らない。

カテゴリの管理ID集合と、PMが実作業のために取得するclaimは別である。実装するownerは元IDごとに一意にする。WIP、未追跡差分、未回収ワーカーがあれば、回収または正当な移管を先に行う。

配置は既存の計画と実装責任、共有ファイル、供給関係、検収負担を基準に決める。新規PMを作る前にカテゴリ自身のchatへ4列の配置表を示す。PMの中核実装、ワーカーの分担、検収方法と工程終了条件はPM自身が5列の開始表で決める。表と送信文は[起動手順](references/task-launch.md)に従う。

実装中・阻害中のIDと未回収成果をWIPとして数え、projectの許可、利用枠、共有資源、回収能力に合わせて配置する。待機のたびにchatを増やさない。固定人数、別進捗DB、汎用スケジューラ、毎成果の承認表は追加しない。

## 調整して作業を再開させる

共通機能には供給・維持の責任カテゴリと受取元IDを定める。受取PMが未配置なら、そのカテゴリが受取責任を持つ。局所問題はPMが解決し、配置・横断供給・共有仕様は関係カテゴリが直接調整する。

カテゴリは必要な履歴・差分・証拠から、対処する担当と次の操作を確認する。是正指示を送っただけで終えず、受取側が必要な版の成果を受け入れ、止まった元IDの作業を再開したことを[点検手順](references/execution-review.md)で確認する。通常の修正・完了や、空いた試験枠の利用にカテゴリのACKは不要である。

起点chatは配置手続きをしただけで上位・報告先・承認先にはならない。カテゴリの結果は自分のchatに示し、他chatへの連絡は[通信条件](references/task-launch.md#起動文へ展開する共通通信文)に限る。利用者との対話を分けても第二の指揮系統にしない。製品範囲、両立不能な保証、権限、費用など、既存権限で決められない変更だけを利用者へ戻す。

## 管理を終える

供給Iの完了と、consumer C/Vの接続・検証の完了は別に確認する。型、fixture、mainへの採用だけで通常経路が使えるとは判定しない。カテゴリは受取先と残るC/Vを追い、PMの担当を原条件外の全consumer完了まで延長しない。

最終統合・横断検証・リリースは、その元条件を持つIDのPMが担当する。他のIDの局所完了を承認する上位者にはしない。

全管理IDの元body/check・必要level、必須統合条件・Vと必要な正式化が終わったことを、同じ進捗正本と証拠で確認する。設定済みの点検タイマーは管理範囲の完了または利用者の停止指示で停止し、結果を確認する。設置と停止の実手順は[カテゴリ内点検](references/execution-review.md)を使う。
