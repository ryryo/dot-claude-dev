# 計画・起動・受渡しの雛形

役割別起動本文と、その組立ての正本。案件固有値は実在参照で埋める。本文は責任・終了点を明示し、詳細手順は正本から展開/参照する。雛形は許可の証拠ではない。

## 起動文の組み立て

1. 新規カテゴリ/PMの該当ブロックを選び、実入力を埋める。現行契約とは適用projectが実際に選んだ配置済み契約であり、未配布のGitHub版や古いsnapshotを現行として渡さない。
2. 下表のmarkerを正本の表またはコードブロック内全文で置換する。これは組立て用の記法であり、実clientのテンプレートAPIではない。表の具体値は起動された担当が決める。markerや置換指示のまま送信しない。
3. 展開本文に必要な参照先、許可、モデル/方式、必要宛先・配送経路を確認済み入力として渡す。宛先一覧から全員連絡・起点報告を自由作文で追加しない。
4. [送信前と起動後の照合](task-launch.md#送信前と起動後の照合)を実本文/実引数で行う。同ID通常再開は既存契約と開始表の参照・差分で足り、全文を組み直さない。

## 単体ID PM

```text
あなたは元ID<対象元ID>一つを原条件の充足と必要な正式化まで担当するPMです。
中核設計・実装・必要な通常接続・worker回収・自己検収・正当なCLI完了を一貫して持ちます。
部分成果・中断・供給待ち後も同じID/chatで続け、別IDをこのchatで始めません。

所属カテゴリ: <カテゴリ名、正式ID/host。起点IDを流用しない>
原依頼/許可: <実指示への参照と操作範囲。移管中なら読取のみ>
対象元ID/原条件: <body/check/必要level、I/C/Vの元範囲の実在参照>
残条件/最初の成果: <充足した条件と証拠、今回減らす条件と必要成果>
既成果/引継ぎ: <採用版・WIP/untracked・未回収worker/依頼回・修正履歴・process・handoff>
供給/受取: <元ID・担当・必要能力/版/環境・解除条件、通常入口/供給先>
正本/owner: <唯一の正本と実CLI、最新revisionの読取、現claim・合法な開始/完了/移管手順>
環境/境界: <実project/host、cwd/開始base、編集/共有操作、PM/workerの認可済み設定・方式>
現行契約: <AGENTS/setup、playing-manager.md、scope-and-gates.md、共通実行ループ・共通配送と必要仕様の確認済み参照>
必要宛先/配送/再開: <所属カテゴリ等の実ID/hostと既許可、確認済みの一つの成果配送経路、その確認根拠、実再開方式/不足>

最新正本・owner・実設定・WIP・原条件を照合し、読取移管段階ではclaim/編集/worker起動を始めません。
実装開始時、自chatに「開始：対象元ID」と次の5列を提示してください。
{{START_TABLE}}
中核実装、worker成果または不使用理由、実モデル/推論と理由、前提/順序・検収を自分で決め、最後の列に今回工程の終了条件を具体化します。
表提示→正当なCLI着手更新→実装/必要なworker起動の順です。通常着手にカテゴリACKは不要です。
同IDの通常再開は、自chatの完全な開始表を現在条件と照合して参照・差分だけで続けます。分担変更・表なし・正式後継の初回は現在の5列を提示します。

{{EXECUTION_LOOP}}

workerは独立owned成果だけを共通task-contractで依頼し、報告先を自分とします。小作業で起動する義務はありません。
通知なしcompleted・未commit成果も回収契約で確認し、同worker修正/引取りまたは前提解消で閉じます。
供給不足やCLI拒否は原条件と現物から是正し、偽done・依存削除・詳細行への迂回をしません。
待機前に回収可能な成果と同IDの非依存工程を確認し、残条件・供給元/受取元・解除条件・再開工程を既存記録に残します。
原条件に必要な通常経路・必要levelを維持し、部品/fixture・main反映だけで元ID完了にしません。
全原条件と必要正式化を閉じたら、元ID・採用版・原check結果・証拠・CLI/commit/必要受渡しを所属カテゴリへ一度通知します。
供給Iと残consumer C/Vは区別し、原条件外の後続全完了まで延長しません。

{{DELIVERY}}

{{COMMUNICATION}}
```

## カテゴリの定期点検タイマー

利用者が設置/更新を依頼した時だけ使う。同じ対象の既存タイマーを確認し、以下の入力と短い現行手順読取本文を保存する。点検アルゴリズム/通信文全文の固定コピーを保存しない。

```text
対象: <既存カテゴリの正式ID/host。起点/点検専用chatへ代替しない>
依頼/許可: <実指示、間隔、終了条件、読取と既承認の是正操作>
全管理ID/正本: <全承認済み集合と原条件、唯一の正本/実CLI、最新値の読取先>
現PM/成果: <既存担当/採用版/未回収/handoffの参照>
現行契約: <配置済みSKILL.md、execution-review.md、共通実行ループ、task-launch.md、templates.mdの確認済み参照>
設定/タイマー: <認可済みモデル/方式/cwd、実対象の識別と既存タイマーIDまたは未作成>

{{TIMER_ENTRY}}
```

設定済みの実対象/保存prompt/間隔と実runを別々に確認する。静的雛形の検証だけで設置・配送・点検済みにしない。

既存記録用の雛形であり、部分成果のたびの送信指示ではない。役割の通信条件と一つの配送経路を使う。

## 移管・統合集約のhandoff

保持する内容と順序は[consolidation](consolidation.md#2-handoffで保持するもの)を参照する。ここに同じhandoff項目の別版を作らない。所有移管と任意のmain集約を区別する。

## 状況照会への返答

結論、実版/証拠と未取得範囲、処置/担当、原残条件の減少または実復帰の確認を既存記録から短く返す。配送/予定だけで改善済みにしない。
