# 計画・起動・受渡しの雛形

案件固有値だけを実在参照で埋める。雛形は認可の証拠ではない。既存記録があれば参照と差分を使い、規則全文・全起動文・日次コピーを繰り返さない。

## 計画と担当範囲

```text
原依頼/実行許可: <実際の指示・承認済み計画>
到達点/全scope: <全元ID、原body/check/必要level、初回/後続/移管の根拠>
正本: <唯一の正本、実CLI/更新手順、現在revision>
体制: <カテゴリごとの管理ID群と責任。未割当・重複も保持>
能力/受取先: <共通契約の責任カテゴリ、供給元ID/版、consumer元IDと受取担当、解除条件>
共有境界: <編集順・試験資源・統合条件の担当、project環境手順>
実行設定/認可: <役割別モデル・推論、方式/開始元、委任・通信・commit・外部実行>
WIP/継続: <projectに即した並行枠、阻害中/未回収、実clientの再開方式と不足>
移管/統合集約: <指示された場合だけ対象・根拠・再開条件>
```

## カテゴリオーケストラ

```text
役割: <カテゴリ>の担当ID群を管理するオーケストラ
管理scope/根拠: <全元ID、原条件、承認済み順序。実作業claimとは別>
正本/CLI/現在revision: <確認済み情報>
他カテゴリ/共通契約: <実宛先と通信許可、契約ごとの供給・維持責任>
現PM/既成果/未回収: <元IDごとの正式chat、採用版、WIP、既存handoff>
次の配置/供給待ち: <開始可能な元ID、受取先と解除条件、未割当>
実行設定/環境/許可: <確認済みのモデル・推論・方式/開始元・操作範囲>
継続方式: <実clientで使える方式と不足>
入口: <gantt-development-orchestrator/SKILL.mdの確認済み絶対パス>
```

カテゴリは配置・順序・横断調整を持つ。PMの中核実装・最終検収を兼務せず、通常完了の承認者やworkerへの別指示元にならない。

## 単体ID PM

```text
役割: 元ID <一つの実在ID> を完了まで持つPM
原条件: <原依頼、元body/check/必要level、I/C/V等の元責任範囲への参照>
残条件/次工程: <既に充足した条件と、最初に減らす未充足条件>
既成果/採用版: <固定Source、consumer版、証拠、WIP/untracked、未回収>
必要能力/供給先: <供給者/版、受取元ID・担当、解除条件>
編集/共有境界: <中核・owned範囲、通常入口、共有試験資源>
正本/CLI/owner: <確認済みパス・更新手順・現claim。移管中なら読取のみ>
設定/環境: <役割別の実モデル・推論、認可方式/開始元、project setup>
カテゴリ/通信: <正式ID・host、実際の許可範囲>
worker/commit/外部実行: <既承認範囲と不足>
回収/再開: <同IDの同chat継続、実clientの方式と未確認>
最初に読む契約: <playing-manager.mdの確認済み絶対パス>
開始時の出力: 契約第3節の開始表を提示→実着手CLI更新→実装/worker起動。同ID継続は整合する完全な既存表を参照。通常着手にカテゴリのACKは不要。
開始表の雛形: <契約第3節の5列Markdown雛形を実送信文へ展開する>
継続元: <同ID再開なら開始表の発言参照。交代なら正式後継のhandoff>
```

開始表の正本は[単体ID契約第3節](playing-manager.md#3-原idの開始)だけ。送信前に展開を確認し、全worker成果をカテゴリが事前設計しない。workerへの依頼は共通の[task-contract](../../codex-task-split/references/task-contract.md)を使用し、報告先は単体ID PMとする。

## 部分供給・同ID継続・元ID終了

```text
対象/現工程: <元ID/checkと実装・接続・検収・正式化等>
成果/証拠: <固定版、owned、前提、検証対象/環境/終了結果>
採用/利用側: <consumer版、受取元ID/担当、未受入、解除する能力>
残条件: <原checkの未充足、失敗・未実施>
次: <同IDで進める工程、または待つ能力/供給者/解除条件>
開始表/継続: <実chatの参照、現在条件との整合または必要な補正>
終了の場合: <元条件の結果、CLI/commit/必要受渡しの実施済みと未完>
```

PMの次工程と、カテゴリが次に配置する別IDを混同しない。受領・採用・main反映・元ID完了を一つの成功で括らない。

## 移管・統合集約のhandoff

```text
根拠/対象: <実利用者指示、元ID/全scope、所有移管か統合集約か>
固定成果: <base/HEAD、owned tracked/untracked、index/WIPの識別と所在>
原条件/証拠: <充足/残件、採用版、実検証・失敗・未実施>
worker/process: <正式thread/依頼回、未回収、編集・書込終了状態>
state保護: <必要時のみprivateな所在/所有/復元方法の参照。内容を転記しない>
所有/受領: <旧担当、新PMの読取受領、正当なclaim移管、未移管の責任>
再開: <新PMの同ID残工程、実設定/前提、開始表、実再開方式>
統合集約の場合のみ: <全差分の処遇、統合担当、検収M、同M再展開条件>
```

## 状況照会への返答

```text
結論: <現在の状態と重要な不足>
根拠: <正本revision、実thread/差分、採用版、証拠、未取得範囲>
処置/担当: <次の実装・回収・供給・是正と、その責任者>
改善確認: <どの原残条件が減り、どの元IDが再開/完了したか>
```
