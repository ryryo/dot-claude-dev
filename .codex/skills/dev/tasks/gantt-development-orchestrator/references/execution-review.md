# カテゴリ内の点検

カテゴリオーケストラが、必要な元IDに絞って実態を確かめる。PMの実装や最終検収は代行しない。問題を発見した場合は[復旧手順](../../codex-task-split/references/execution-loop.md)を使い、必要な成果の受入と、止まった元IDの作業再開を確認する。

## 適用する契機と許可

新規配置の判断前とPM配置後、供給・依存・成果受入の変化、停滞や反復の疑い、状況照会で点検する。全PMへの質問やACKを前提にしない。定期点検の設置・更新は、利用者から対象カテゴリと間隔を指定された場合だけ行う。停止済みタイマーの再開には、停止後の明示許可が必要である。

## 点検手順

### 1. 現行契約と変化を読む

最新の利用者指示、配置済みの現行契約と、既存chat・note・handoffにある前回の契約版・観測点を確認する。集中計画・休止・所属変更の文書を実配置済みと扱わず、過去の起動やタイマー設定で現在の停止指示を上書きしない。必要な手順と変更を読み、毎回の全資料・全履歴の監査にはしない。前回を特定できなければ初回として扱う。

最新の正本と既存CLIの読取結果を元IDで照合し、全管理IDの状態、owner、依存、原check、未回収と正式化を確認する。owner検索やready一覧だけに絞らない。実在しないCLI項目や新しい台帳は要求しない。初回は全範囲、その後は前回からの変化と未解決候補について必要な履歴・差分・証拠を読む。

次は再評価の候補であり、そのまま状態更新する条件ではない。

- 着手済み未完IDのownerが、停止・アーカイブした旧担当のまま、または実担当と一致しない。既成果と実編集状態を確認し、同PMで継続できれば戻す。交代が必要なら[正式移管](consolidation.md#1-単体id担当への所有移管)の許可と手順を確認し、無断でclaimを奪わない。
- blockedの解除条件に必要な供給や依存が変わった。現PMが受取版・環境・実能力と合法な開始条件を再評価し、同じ元IDの次工程へ戻る。登録上の依存充足だけでは解除しない。
- 既存CLIのcanComplete等が完了可能を示す未完ID、または検収後の正式化だけが残るID。現PMが元body/check・必要levelと現在の証拠を確認し、[通常の完了処理](playing-manager.md#3-原idの開始)へ戻る。カテゴリが表示だけでdoneにせず、未実施や古い証拠を残す。
- 待機先が役割名だけで、供給元ID・owner・正式chatを特定できない。関係カテゴリが[供給責任](category-coordination.md#3-横断依存循環未所有仕事)を既存IDへ結ぶ。未配置なら担当を確定するカテゴリと次操作を残し、架空の供給担当を前提に待たない。

点検の稼働・配送と、対象PMの実行能力は分けて確認する。必要な編集・実行・続行送信が実環境で可能かは、現在の許可と実ツール結果を根拠にし、点検の成功から推測しない。実行能力の不足と製品の供給待ちの次操作は、共通の[原因別手順](../../codex-task-split/references/execution-loop.md#2-原因に合わせて一つの次操作を選ぶ)で選ぶ。

実行中表示と工程の動きが食い違う候補は、[実操作・processとの照合](../../codex-task-split/references/execution-loop.md#1-現物と次の判別点を結ぶ)へ進む。原条件の充足、原因の絞込み、固定成果の実供給は前進として区別し、全未完を放棄と扱わない。経過時間、報告量、通信量の減少だけで停滞や完遂の改善を判定しない。

### 2. 起動・責任・工程を照合する

新規配置があった時は[起動前後の照合](task-launch.md#送信前と起動後の照合)を行う。カテゴリの4列表、PMへ送った元条件と実行本文、PM自身の5列表、CLI着手と実装の順序を実記録で確認する。通常再開での適正な表参照を漏れとせず、読取起動に実装を要求しない。

部分成果の後に、[PMの残工程](playing-manager.md#3-原idの開始)のどの原条件へ進んだか、または何が妨げたかを確認する。既存PMの完遂と必要供給を[配置の判断](task-launch.md#カテゴリオーケストラ)へ戻し、新規起動数を成果にしない。追加の実装・調査・抽象化・試験が必要かは[工程の基準](../../codex-task-split/references/execution-loop.md#起動文へ展開する工程本文)に従う。

通信が多い場合は、該当PMの最近の実送信を少数確認する。実ツールの宛先と本文を[送信条件](task-launch.md#起動文へ展開する共通通信文)へ照合し、相手に必要な判断・操作、前回からの操作条件の変化、同じ入力固定中の実況や既知内容の再掲を確認する。PM間とカテゴリ間で同じ共有仕様を二重採用していないかも見る。不要な用件は具体例を示して該当PMへ是正し、その後の実送信と作業継続で確認する。全PMへの質問やACKを求めず、手順の再読だけで是正完了としない。必要な相談・解放・供給と一つの[配送経路](../../codex-task-split/references/delivery.md)は維持する。

### 3. 必要な復旧だけ閉じる

局所問題はPMが解決する。未担当や横断供給、共有仕様の問題は関係カテゴリが[直接調整](category-coordination.md)し、能力とCLIの判定は[scope契約](scope-and-gates.md)に従う。共通の原因判別や再開手順をここで別に定義しない。

カテゴリは[復旧手順第1〜3節](../../codex-task-split/references/execution-loop.md#1-現物と次の判別点を結ぶ)で、実際に止まった元ID/check、解決担当と再開担当を対応付け、解除条件に必要な変化を追う。処置後は必要な版の受入と同IDの実操作再開を確認する。解除だけ確認できた場合は実再開待ちを残し、是正文を周期ごとに再送して済ませない。

理由の出典・古さと現在の担当・前提を照合し、不足や条件が変わった場合は権限を持つ現PMが適用先の合法CLIで記録を更新する。カテゴリが表示のために他PMのownerを使ったり、未記録の本人操作・実行状態を埋めたりしない。供給担当が未確定の間は、カテゴリが担当確定の責任を持つ。通知の件数や既読ではなく、同じ正本の原条件と受入・再開の観測で確認する。

開始表などの漏れは現在状態で補正し、過去に実施済みとは記録しない。成果、claim、証拠、修正履歴を保持する。変化のない外部待ちは解除条件に必要な変化だけ確認し、同じ催促や全試験の再演を行わない。

### 4. 結果と実タイマーの終了

重要な進展、是正、失敗、利用者判断がある時だけ、自カテゴリchatへ結論・根拠・処置・担当を短く示す。既存記録には必要な版と、どの元IDが再開したか、または未再開かを残す。起点報告、定期ACK、変化のないnote・CLI更新、全管理IDのコピーは増やさない。

設定済みタイマーは、全管理IDの原条件と必要な正式化が完了した時、または利用者の停止指示時に、実ツールで対象を停止して結果を確認する。部分成果、一PMの終了、外部待ち、停止文の記載だけでは停止済みにしない。結果不明なら照会し、未停止・未確認を明示する。

## カテゴリの定期点検タイマー

設置・更新が許可されている時だけ、既存カテゴリchatに対応する実ツールを使う。停止済みなら、保存promptの更新を再開へ読み替えない。休止IDを含む管理範囲を保持していても、点検を常時稼働させる義務にはしない。同じ対象のタイマーID・host・設定を照合し、重複作成しない。結果不明なら既存設定を照会する。未対応の機能を起点の監視、新chat、cron、daemonで代用しない。

次の入力と読取指示を一つの保存promptにする。`<…>`を実値で埋め、点検アルゴリズムや通信規則の全文はコピーしない。

```text
対象カテゴリ: <既存カテゴリの正式chat IDとhost>
依頼と許可: <利用者の実指示、間隔、終了条件、承認された読取りと是正操作>
全管理IDと正本: <全承認済みID集合、元条件、唯一の正本と実CLI、最新値の読取先>
現担当と成果: <PM、採用版、未回収成果、handoffの参照>
現行手順: <配置済みexecution-review.mdの確認済み参照>
実行設定とタイマー: <認可済みモデル・推論・方式・cwd、対象の識別方法と既存タイマーIDまたは未作成>

現行手順を読み直し、「点検手順」に従って自カテゴリを点検してください。必要になった契約変更だけを参照し、保存promptや過去の手順コピーを正本にしません。
最新の停止指示を確認し、停止対象の点検から実装再開・再送を起こしません。許可、モデル、対象chat、間隔、終了条件は変えません。手順を読めなければ点検未実施として不足を残し、古い全文を推測して実行しません。独立した通常作業や明示された停止操作まで妨げないでください。
変化のない外部待ちには催促せず、起点報告、定期ACK、全PM同報を行いません。
全管理IDと必要な正式化の完了、または利用者の停止指示があれば、この実タイマーを停止して結果を確認してください。
```

古い全文promptを使うタイマーも、既存の設置・更新許可の範囲で同じ対象を更新する。文書改修の依頼だけでは実配置しない。保存prompt、対象chat、間隔、設定と少数の実runを照合する。配送時刻だけで指定間隔の点検や強制割込みを保証せず、点検のために試験や書込processを止めない。

## カテゴリ起動文へ展開する点検文

起動時の最小責任は[カテゴリ送信本文の「点検と終了」](task-launch.md#カテゴリオーケストラ)に統合した。別の点検本文を重ねて展開しない。

## 点検手順とタイマー本文

旧参照の案内。設定時は[タイマーの入力と保存本文](#カテゴリの定期点検タイマー)、実行時は本書の「点検手順」を使う。

## 設定変更と実観測

prompt保存、配送、点検の実行、是正操作、成果受入、同IDの再開は別々に確認する。文書の検査と机上の組立てだけで、実clientの挙動や運用改善を実証したとは扱わない。
