# カテゴリの実行点検

カテゴリ自身が原残条件・実起動・成果・反復を必要な範囲で照合する正本。点検は問題を発見して指示するだけで終わらず、[共通実行ループ](../../codex-task-split/references/execution-loop.md)へつなぎ、実成果の受入と元IDの実復帰まで確認する。PMの実装/全検収、第三の管理役、別台帳を追加しない。

## 適用する契機と許可

PM配置後、供給/成果受入、停滞・反復・範囲拡大の疑い、状況照会で必要な範囲を点検する。通常作業へのACKや全PMへの質問を前提にしない。

定期点検は利用者が対象カテゴリと間隔を指定して依頼した場合だけ、実clientが対応する既存カテゴリchatへ設定/更新する。文書改修・タイマー案は実配置の許可ではない。同対象の既存タイマーID・対象chat/host・設定を照合し、重複作成しない。結果不明は再照会する。

実ツールが対象chat・間隔・既認可設定を扱えるか確認する。未対応なら不足を示し、起点監視・新chat・shell cron・daemonへ暗黙代替しない。配送時刻は実点検turnや強制割込みの保証ではなく、書込processや試験を点検のために強制停止しない。

## カテゴリ起動文へ展開する点検文

次の短い責任本文をカテゴリ起動へ展開する。詳細手順の写しは持たず、通常の配置/回収/停滞時も同じ現行の第1〜4手順を使う。

```text
【カテゴリ内点検】
配置・供給/受入・停滞/反復・状況照会では、現行execution-review.mdと関係する契約変更を読み、必要な元IDへ絞って実態を照合してください。
局所問題はPM、配置/横断供給/共有契約は関係カテゴリが共通実行ループで処置し、実成果受入と同IDの実復帰まで追います。
PMの中核実装・最終検収を重ねず、同じ催促・全試験再演・全PM再送を行いません。
定期点検は利用者が設置を依頼した時だけ既存カテゴリchatの実ツールで設定し、既存タイマーを重複作成しません。
全管理IDと必要な正式化の完了、または利用者の停止指示で、設定済みの実タイマーを停止して確認します。
```

## 点検手順とタイマー本文

この見出しは旧参照の入口を保持する。保存するのは以下の読取起動文だけで、点検アルゴリズムや通信規則の全文をタイマーへ固定しない。[templates](templates.md#カテゴリの定期点検タイマー)の実値と組み合わせる。

```text
既存の対象カテゴリchatとして、入力の現行契約参照からexecution-review.mdを読み直し、その「点検手順」を実行してください。
そこから必要な現行の共通実行ループ・通信・起動/PM契約の変更を読み、保存promptや過去の手順コピーを正本にしないでください。
入力の全管理ID、唯一の正本、既存担当/handoff、前回の観測点を使います。許可・モデル・対象chat・間隔・終了条件を広げません。
手順を読めなければ点検は未実施として不足を残し、古い全文を推測して実行しません。非依存の通常作業や明示された停止操作まで妨げません。
変化のない外部待ちは静かに保持し、起点報告・定期ACK・全PM同報をしません。
全管理IDと必要正式化の完了、または利用者の停止指示があれば、入力に対応する実タイマーを止めて確認してください。
```

## 点検手順

### 1. 現行契約と変化を読む

実在する配置済み契約の入口と、前回の契約版/観測点を既存chat/note/handoffから確認する。今回必要な手順と変更だけを読み、毎回全資料や全履歴を再演しない。新しい手順を読んだことは権限・モデル・scopeの変更ではない。

最新正本、全管理IDの担当/未担当/供給待ち/正式化残、前回以降の必要な実turn・差分・試験結果を確認する。一次確認から疑いのある元IDへ絞る。前回不明なら初回観測として扱い、過去の変化や実施を推測しない。

### 2. 起動・責任・工程を照合する

新規配置があった時だけ[起動前後の照合](task-launch.md#送信前と起動後の照合)を使う。作成前のカテゴリ4列、元ID/原残条件/許可、正本から展開した実起動文、PM自身の5列と工程終了条件、CLI着手と実装の順序を見る。通常再開の適正な表参照を漏れとせず、読取起動に実装を要求しない。

全管理IDの未担当・重複owner・残WIP・未回収、供給成立後の未再開を確認する。既存権限/WIP枠内で必要な配置と復旧を行う。経過時間やID未完だけで停滞とせず、原条件充足、原因の絞込み、供給成立という実進展を見る。

追加の実装/調査/抽象化/試験が原条件・確定仕様・実不具合・今回の変更に必要かを共通実行ループで確認する。必須CI/Gate・実サービス/OS・安全性を削って短時間化しない。通信は[共通通信文](task-launch.md#起動文へ展開する共通通信文)、成果の二重送信は[共通配送](../../codex-task-split/references/delivery.md)と実方式で判断し、途中連絡を一律に不要と決めない。

### 3. 必要な復旧だけ閉じる

問題を元ID/check・実不足・解決/再開担当・最小の次操作・供給元/受取元・対象版/環境・解除条件へ結び、共通実行ループを実施する。カテゴリはPMの実装を代行せず、共有契約は[関係カテゴリの直接調整](category-coordination.md)、能力/CLIは[scope契約](scope-and-gates.md)を使う。

是正は必要な担当だけへ渡し、送信・受領・予定を解消としない。受入版の実成果と、止まっていた元IDの実工程を観測する。効かなければ前回の操作と現物を比べて未実施・供給不足・版/環境・CLI拒否・配送/再開の不足を分け、次操作を修正する。同じ文面を周期ごとに再送しない。

手順漏れは現在状態で補正し、過去に提示済みと記録し直さない。成果・claim・証拠・修正履歴を保持する。必要工程が成立すれば次の原残条件/正式化へ進ませ、根拠のない追加改善で延長しない。未変化の外部待ちは解除に必要な変化だけ読み、催促・再監査を止める。

### 4. 結果と実タイマーの終了

処置/判断に必要な観測版・実成果・復帰/未復帰を既存記録へ対応させる。是正・重要な進展・失敗・利用者判断がある時だけ自カテゴリchatへ結論・根拠・処置・担当を短く示す。起点報告、点検ACK、変化のないnote/CLI更新や全管理IDコピーを増やさない。

設定済みタイマーは、全管理IDの原条件と必要正式化を閉じた時、または利用者の停止指示時に実ツールで停止し、対象IDと停止結果を確認する。部分成果、一PM終了、外部待ち、停止文の記載では停止済みにならない。結果不明は照会し、未停止/未確認を隠さない。

## 設定変更と実観測

旧タイマーに長い手順コピーがある場合、利用者の実際の設置/更新許可内で同じタイマーを読取入口へ更新する。許可外なら必要な変更を示すだけにし、スキル改修から実更新を開始しない。保存された実prompt・対象chat/host・間隔・設定と少数の実runを照合する。

prompt保存、配送、実点検、是正操作、実成果受入、同ID再開は別の確認点。文書と机上組立てだけでclient実動作や指定間隔の点検を証明しない。
