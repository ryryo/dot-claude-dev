# 動作ベースの回帰確認

スキル改訂・停滞是正に使う。架空条件による試行であり、project検証・実client動作の証明ではない。全製品taskへ追加Gate・常設監視・新台帳を課さない。本文キーワード一致ではなく、判断主体、実際に読む/起動/回収/開始する動作、採用版、保持した残checkで評価する。

## 最初の四試行

1. **scope・採用・次ID**：小さな架空正本と欠落報告を使い、実際の判断出力が分母を回復し次の原条件へ向かうか確認する。
2. **一つの実workerの回収**：別途認可された独立chatで、未commit、親の待機前completed、通知不達、同worker修正、重複通知を観測。親終了後/client再開は実際に観測できた範囲だけ合格とする。
3. **project CLI**：隔離fixtureで開始可/完了不可、能力なし拒否、旧edge互換、版変更、循環、同時revisionを確認。製品の原IDを試験用に偽doneにしない。
4. **Mへの集約**：隔離repoで全差分処遇・M開始・戻し方を確認。

独立chat試行はAPI追加課金がなくてもモデル利用枠を消費し得る。試行の許可・設定・対象を別に確認する。

## 合格・rollback

実際の入力版、使用契約版、設定、行った操作、結果、未確認を既存改訂記録または会話に残す。配布ファイルの整合性確認とモデル判断/実client/製品CLI/実APIの試行を別々に扱う。

原scope/許可の欠落、未回収、二重正式化、機械迂回、M不一致、state破壊があれば該当改修を不合格にする。文書/CLIの改修を前版へ戻す場合も、成果・証拠・正本履歴を消さない。スキル文書が通っただけで実行体制の是正済みとは報告しない。
