# 全scopeを持つ担当の起動

実行オーケストラが使う。実際の作成・許可・モデル・環境・正式IDは[共通実行条件](../../codex-task-split/references/execution-context.md)に従う。worker起動は各PMが[codex-task-split](../../codex-task-split/SKILL.md)で行い、Rootが全Luna成果を設計しない。

## 起動する側

1. 計画と実開始指示、現在モード、全原scope、既存owner/worker/未回収、必要能力を確認する。統合集約で新規起動が止められている間は、同じ計画にあることだけで起動しない。
2. 実project/host、認可済み方式と開始元、モデル/推論、正本パス、環境手順、通信先を確認する。継続方式の利用可能性と認可を確認し、未確認の自動再開を約束しない。
3. [起動テンプレート](templates.md)で、全ID/原根拠/元check、順序、採用済みと保留、専有境界、直接の報告先、既許可と不足、担当入口の実在する絶対パスを渡す。初回IDだけに縮めない。非公開資料を公開repoへ転記しない。
4. 実schemaの `create_thread` で起動し、正式ID・実タイトル・model/effort・方式・cwd/HEADを対応付ける。pendingは正式IDとして使わず、結果不明は照会してから再試行する。
5. 初動の全scope対応と最初のID・分担を照合する。責務漏れ・不正な開始元だけを訂正し、適正な着手をRootのACK待ちにしない。起動成功/開始確認/実装完了を分けて報告する。

## PMへ渡す実行入口

[playing-manager](playing-manager.md)を最初に読むよう直接指定する。PMは初動、原ID開始、実装/委任、回収/検収、正式化、次IDを自律的に実行する。正本は一つ、workerの報告先はそのPM。通常の局所修正・次IDの選択にRootの都度承認を挟まない。

## 通信する内容

| 宛先 | 必要な通信 |
| --- | --- |
| worker→PM | 検収依頼または判断待ち。成果版、編集状態、証拠、未完を送る。 |
| PM↔関係PM | 許可された共有境界の調整、固定能力の供給/受入。呼出元・解除条件・残件を明示する。 |
| PM→実行役 | 統合に必要な供給、担当間で解けない判断、全scope終了、指定された移行handoff。 |
| 対話役↔実行役 | 原要求・利用者が選ぶ事項・判断根拠・実態照会と是正。第二のPM指揮系統を作らない。 |

通常の試験・局所修正・worker待機は担当chatと正本へ残し、上位へ全文転送しない。状況照会・明示報告頻度には従う。必要な判断は根拠・影響・推奨案・決める点を送る。実作業のないACKを相互再起動の理由にしない。

## 終了済み親への接続

起動時に回収先と再開方式を記録する。親は[共通回収契約](../../codex-task-split/references/main-review.md#1-回収と再開)に従い、待機前/再開時に実threadを照合する。成果通知がなくてもcompletedの現物を回収する。親終了後のfollow-up、明示Goal/heartbeat等の実client対応が未確認なら、その部分を未確認とする。

送信失敗とworker失敗は別。待機中は同じ相手を短間隔pokeせず、イベント待機と必要な照会を使う。実clientが止まった状態で永続継続できるとは報告しない。
