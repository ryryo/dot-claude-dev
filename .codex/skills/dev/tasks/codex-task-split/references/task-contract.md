# ワーカーへの依頼と報告本文

起動者は依頼文を組み立て、ワーカーは成果報告に必要な項目を使う。許可・実設定は[共通実行条件](execution-context.md)、送信経路は[delivery](delivery.md)に従う。報告項目の正本は本書に置き、配送資料に別版を持たない。

## 起動メッセージ

原依頼と既存正本を参照し、今回の担当成果、残条件、終了条件、必要な補足を渡す。実在するID・宛先・参照先を使う。作成後にしか分からないworkspaceは、作成後の確認を明記する。

`{{EXECUTION_LOOP}}`を[工程本文](execution-loop.md#起動文へ展開する工程本文)、`{{DELIVERY}}`を[配送本文](delivery.md#起動文へ展開する配送本文)のコードブロック全文で置換する。入力を埋めたら、未展開marker・仮値と実起動引数を照合する。

```text
作業: <元作業IDと担当成果の識別> / 依頼回: 1
原依頼と残条件: <実在参照と今回満たす条件>
成果と終了条件: <最小の担当成果、必要な利用動作・失敗条件、検証と工程終了条件>
編集範囲と前提: <担当する責務、指示元の実装との接点、採用版、保護する差分>
実行設定と環境: <認可済みモデル・推論、project、host、方式、開始元、cwdまたは作成後の確認、setup>
直接の指示元: <正式thread IDとhost>
成果配送: <確認済みの自動最終回答または手動送信の一経路、確認根拠、実ツールと宛先>
相談と再開: <必要な親判断・共有操作の許可済み経路、実再開方式と不足>
現行契約: <worker-work-contract.mdと展開する工程・配送本文の確認済み参照、必要仕様>
利用者の許可: <実指示への参照、承諾済み操作。commit・公開など未承認の操作も区別>
補足: <引き継ぐ必要のある事実だけ>

あなたは上記の成果を担当する限定ワーカーです。調査・局所設計・実装・検証・修正まで進めてください。
局所判断は自分で行い、未決の共有契約や担当外操作は直接の指示元へ戻します。再委譲や共有進捗の完了判断はしません。

{{EXECUTION_LOOP}}

成果は原則未commitで渡します。担当差分とuntrackedの所在、対象版・環境に対応する証拠、残件、編集と書込processの終了状態を示してください。
採否と原ID完了は指示元が決めます。必要な親判断は完了まで持ち越さず相談してください。

{{DELIVERY}}
```

独立chatの指定を自動配送のために別方式へ変えない。ワーカーは起動文で渡された責任を再掲するために全手順を読み直さず、未決判断時には作業契約の該当節を読む。

## 担当記録

既存の担当欄またはhandoffへ、委任した作業だけを記録する。必要なのは編集範囲と依存、正式thread ID・host・返却タイトル、workspaceと開始base、依頼回、成果版、観測cursor、配送経路と結果、採否・採用版、未完の処理への参照である。

not_started、starting、running、review_ready、accepted、rework、blocked、corrected-by-main、rejectedは説明に使えるが、projectのstatusを置換・追加しない。pendingは正式IDと区別し、共有正本はワーカーではなく指示元が実観測から更新する。

依頼回は初回1、具体的な修正・再開ごとに更新する。品質修正回数とは別であり、環境復旧や判断回答を品質失敗に数えない。同じ成果の履歴をchatの作り直しでリセットしない。

## ワーカーからの報告

次は報告内容の雛形であり、手動送信命令ではない。選択した経路で一度渡す。

```text
ワーカー報告: <作業ID> / 依頼回: <回数> / review_ready または blocked
送信元と作業先: <正式thread ID、host、実workspace>
成果版: <開始base、担当するtracked・untracked差分の固定識別>
成果と原条件: <変更要約、残条件への結果、重要な判断と理由>
検証: <対象版・依存・環境、実command・selector、実対象と終了結果、証拠参照>
受渡し: <担当差分とuntrackedの所在、適用前提、許可済みcommitがあればその版>
残件と判断待ち: <根拠、影響、推奨案、決めてほしい点、止めた範囲>
編集状態: <編集と書込processの終了、または未終了と影響>
配送状態: <選択経路。手動は実結果、自動は提出と受領未確認を区別>
```

判断待ちは作業ID、依頼回、送信元と、質問の根拠・影響・推奨案・決める点・停止範囲でよい。完成用の欄を埋めるために調査を続けない。探索履歴や全ログは送らず、検収に必要な証拠を参照する。

## 修正依頼

[引取り基準](main-review.md#指示元への引き取り)に従って同じワーカーへの修正を選んだ場合、同じchatと認可済み設定を使う。具体的な修正、親判断、再開範囲だけを許可された経路で送り、元依頼を作り直さない。

```text
ワーカー修正・再開: <同じ作業ID> / 依頼回: <前回+1>
修正点と判断: <必要な挙動と根拠、採用する契約、再開してよい範囲>
変更した前提: <版・環境・編集範囲などの差分>
元の依頼と現行作業契約に従って修正・検証し、選択済みの配送経路で成果を渡してください。
```

受領・採用ACKには返信を求めない。配送結果不明はdelivery、回答後も作業が動かない場合はexecution-loop、品質上の引取りはmain-reviewの該当手順を使う。
