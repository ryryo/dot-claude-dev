# ワーカーチャットの依頼と報告

workerの入力/成果payloadと依頼回の正本。判断境界は[worker-work-contract](worker-work-contract.md)、許可/起動は[codex-task-split](../SKILL.md)、工程終了/復旧は[execution-loop](execution-loop.md)、配送手段は[delivery](delivery.md)、採否/修正/引取りは[main-review](main-review.md)が持つ。同じ配送命令や工程本文を別版として維持しない。

## 起動メッセージ

原依頼・既存正本を参照し、今回のowned成果・原残条件・終了条件・必要補足だけを渡す。全受入条件や内部設計を委任のために作り直さない。実在するID/宛先/契約パスを使い、作成後にしか分からないworkspaceはその確認工程を明示する。

次の実入力を埋め、`{{EXECUTION_LOOP}}`を[工程本文](execution-loop.md#起動文へ展開する工程本文)、`{{DELIVERY}}`を[配送本文](delivery.md#起動文へ展開する配送本文)のコードブロック内全文で置換する。実送信前に未展開marker・仮値と実起動設定を照合する。上位の全手引書は展開しない。

```text
作業: <元作業IDとowned成果の識別> / 依頼回: 1
役割: 直接の指示元が切り出した限定ワーカー。再委譲と共有進捗の完了判断はしない
原依頼/原残条件: <実在する参照と今回減らす条件>
成果/終了条件: <最小のowned成果・必要な利用動作/失敗条件・検証と工程終了条件>
編集境界/前提: <責務/範囲、指示元の中核実装との接点、採用版、保護する差分>
実設定/環境: <認可済みモデル/推論、project/host、方式/開始元、cwdまたは作成後の確認、setup>
直接の指示元: <正式ID/host。配送元情報から推測しない>
成果配送: <確認済み自動最終回答または手動送信の一経路、確認根拠、実ツールと対象>
相談/再開: <必要な親判断・共有操作の既許可経路、実再開方式と不足>
現行契約: <worker-work-contract.md、execution-loop.md、delivery.mdと必要仕様の確認済み参照>
利用者の許可: <実指示への参照と承諾済み操作範囲。commit/公開等は勝手に追加しない>
補足: <引継ぐ必要のある事実のみ>

担当範囲の調査・局所設計・実装・検証・修正まで行ってください。
既存契約内の局所判断は自分で行い、未決の共有契約・担当外操作は直接の指示元へ戻してください。

{{EXECUTION_LOOP}}

成果は原則未commitで、owned差分/untracked、対象版/環境の証拠、残件、編集/書込終了状態を固定して渡してください。
採否と原ID完了は指示元が決めます。判断待ちは必要になった時点で相談し、完了報告まで持ち越しません。

{{DELIVERY}}
```

通常は依頼文と作成先chatを記録にする。起動方式と成果配送方式は別の選択であり、自動配送を使うために認可済み独立chatを別方式へ置き換えない。

## 担当記録

既存の担当欄/handoff/refへ、委任した作業だけ、境界・依存、正式worker ID/host・返されたタイトル、実workspace/base、依頼回、成果版、観測cursor、選択した配送経路/結果、採否/採用版、正式化残を必要時に対応させる。未委任taskまで欄を埋めない。

説明状態はnot_started/starting/running/review_ready/accepted、必要ならrework/blocked/corrected-by-main/rejectedを使えるが、projectのstatusを追加/置換しない。pendingは正式IDにせず、workerは共有正本を更新しない。親が実観測から記録する。

依頼回は初回1、具体的な修正/再開ごとに更新する。品質修正回数とは別で、環境復旧や判断回答を品質失敗へ数えない。原scope・証拠・履歴をchatの作り直しでリセットしない。

## ワーカーからの報告

以下は成果の内容の雛形であって手動送信命令ではない。選択した配送経路で一度渡す。自動最終回答には同じ全文の手動報告を追加しない。手動方式の自chat最終回答は結果参照と配送状態だけにする。

```text
ワーカー報告: <作業ID> / 依頼回: <回数> / review_ready または blocked
送信元/作業先: <正式ID/host、実workspace>
成果版: <開始baseとowned tracked/untrackedの固定識別>
成果/原条件: <変更要約、原残条件への結果、必要な判断理由>
検証: <対象版/依存/環境、実command/selector、実対象と終了結果、証拠参照>
受渡し: <owned差分/untrackedの所在、適用前提、許可済みcommitがあればその版>
残件/判断待ち: <根拠・影響・推奨・決める点・止めた範囲>
編集状態: <編集/書込process終了、または未終了と影響>
配送: <選択経路、手動は実結果、自動は提出と受領未確認を区別>
```

判断待ちは作業/依頼回・送信元・根拠/影響/推奨/決める点・停止範囲でよい。完成用の欄を埋めるために調査を続けない。全ログ・探索履歴を送らず実在証拠を参照する。送信元が自動配送後の結果を観測できなければ受取側が確定し、架空の配送済み表現をしない。

## 修正依頼

送信前に[引き取り条件](main-review.md#指示元への引き取り)を適用する。同じworker・既認可モデル/推論を保ち、実ツールが対応する許可済みの経路で具体的な修正/判断/再開範囲だけを渡す。元依頼を再作成せず、受領・採用ACKに返信を求めない。

```text
ワーカー修正・再開: <同じ作業ID> / 依頼回: <前回+1>
修正点/判断: <必要な挙動・根拠、採用する契約と再開範囲>
変更した前提: <版/環境/境界など必要な差分のみ>
元の依頼・現行作業契約・選択済みの成果配送経路に従い、同じ成果の残工程を修正・検証して渡してください。
```

回答が実前提を解決したかと同workerの実再開も確認する。配送不明はdelivery、是正が効かない時の原因判別はexecution-loop、品質上の引取りはmain-reviewへ戻す。
