# 成果配送・判断相談・再開の共通契約

本書は「どう届けるか」の正本。誰に何を送る必要があるか、元IDの完了責任は呼出元の役割契約に従う。特に大規模モードの起点chatやsource_thread_idは報告先を指定しない。許可・モデル・実ツールは共通実行条件から引き継ぐ。

## 1. 起動時に成果配送を一つ選ぶ

起動者が実client/hostの仕様・実設定・観測可能な挙動から、最終回答の配送先、配送される内容、親を再開できる条件を確認する。確認済みの直接の指示元と、一つの成果配送経路を起動入力/既存委任記録へ残す。自動配送の有無をモデル名や起動元IDから推測しない。

| 実方式 | 成果の渡し方 |
| --- | --- |
| 最終回答が直接の担当PMへ自動配送されることを確認済み | 最終回答を一つの成果報告にする。同じ成果を手動送信しない。発行前に「配送済み」とは書かず、自動配送経路への提出と実受領を区別する |
| 独立chat等で最終回答が自動配送されない | 許可された実送信ツールで直接の指示元へ一度渡す。自chatの最終回答は結果参照・配送状態だけにし、同じ全文を二度送らない |
| 自動配送が未確認、または自動宛先が担当PMと異なる | 未確認の自動配送を採用しない。既許可の手動経路が使えれば選択し、誤宛先への自動転送を実設定で防げるか確認。制御できず保護する経路と衝突する起動は保留する |
| 配送ツール/経路が使えない | 自chatへ報告本文と未送信/配送未確認を残す。指示元は読取回収可能な現物を回収する。使えない経路を配送成功としない |

ここでのnative自動配送は成果の配送方式であり、独立chat指定をsubagentへ置き換える許可ではない。選んだ方式を途中で黙って変えない。既存担当では実方式を確認して差分だけ引き継ぎ、再起動や不要な試験送信をしない。

## 起動文へ展開する配送本文

呼出元の起動雛形は、確認済みの配送入力と以下の全文を展開する。全client共通の手動報告命令を別に足さない。

```text
【成果配送】
起動入力で確認した直接の担当と、一つの成果配送経路を使ってください。
最終回答が直接の担当へ自動配送される方式では、その最終回答に成果・証拠・残件・編集終了をまとめ、同じ報告を手動送信しません。
自動配送されない独立chatでは、許可された実送信ツールで一度渡し、自chatの最終回答には結果参照と配送状態を残します。
未確認の自動配送を仮定せず、宛先不一致や利用不能は未送信/未確認として保持します。
必要な親判断・実共有操作の相談は、最終報告まで保留せず許可された経路で行います。進捗だけの通知・受領ACK・供給予定・変化なし催促は追加しません。
報告単位は作業ID・送信元・依頼回・成果版です。結果不明は宛先履歴や実状態を照会し、届いた報告を再送しません。
配送・親の再開・検収・元ID完了は別々です。返事がないだけで親を繰り返し起こしません。
```

## 2. 成果・判断待ちの内容

成果には作業ID、送信元の正式ID/host、依頼回、成果版、owned差分/untrackedの所在、実検証の対象版/環境/結果・証拠、残件、編集と書込processの終了状態を持たせる。HEADだけでWIPの版を識別しない。秘密・鍵・個人profile・制作stateを報告やhash一覧へ含めない。

成果報告の発行後は固定版を勝手に動かさず、具体的な修正・再開指示があれば新依頼回/成果版で渡す。動く差分や止まらない書込processがあれば検収可能とせず状態を示す。未commitは通常の受渡しであり、配送のためにcommit許可を追加しない。

判断待ちは、その判断が必要になった時点で根拠・影響・推奨・決める点・止めた範囲を渡す。完了欄を埋めるための追加調査は不要。最終回答でしか相談できない実方式ではblockedの最終回答として一度渡し、対応する回答後に同じ担当で再開する。途中連絡が可能なら必要な相談だけ送る。最終回答の自動配送は、途中の相談も自動配送される証拠ではない。

既に途中送信した同じ判断待ちを最終回答でも全文送らない。参照と未解決状態、またはその後の新しい成果だけを示す。親の実判断・入力固定/解放・必要な受渡しは維持し、全ての途中メッセージを不要と断定しない。

## 3. 結果不明と未配達

配送単位は「作業ID + 送信元の正式ID + 依頼回 + 成果版」。同じ単位の宛先履歴・返却結果を照合し、到着済みなら再送しない。成果がない判断相談は該当工程/質問の識別を使う。

手動送信で未着が確認できた場合だけ同じ単位を一度再試行する。自動配送の失敗でも、未配達が確定し手動救済が既許可なら同じ単位を一度渡せる。確認不能や再失敗は未確認/未送信を残し、複数経路へ一斉送信しない。送信元が発行後の状態を読めない場合、受取側の観測で確定し、自己ACKを要求しない。

直接の指示元は、通知の有無にかかわらず回収契約に従って実threadとowned成果を読む。重複・古い依頼回から再commit/再done/再修正しない。配送成功でも親が停止していれば、使える認可済みfollow-up等と実再開を区別して確認する。利用不能なら実際の再開点と不足を残し、無許可の監視・cron・daemonを作らない。
