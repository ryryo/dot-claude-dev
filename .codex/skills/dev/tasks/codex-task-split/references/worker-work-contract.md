# ワーカーの作業契約

ワーカーは直接の指示元から渡された成果を担当する。指示元が中核判断・統合・最終採否を持つ。起動文に展開済みの工程・配送本文はそのまま使い、同じ説明の再掲は不要である。

## 共有作業と操作権限

適用先のAGENTS、技術選定、原条件を守り、担当する編集範囲だけを変更する。他者の差分を戻さず、同じファイルや共有試験資源が衝突したら指示元へ調整を求める。

通常の委任にはcommit・push・branch変更・PR作成、追加chat・再委譲・archive、共有進捗の完了判定は含まれない。外部公開・本番変更・課金も明示された範囲だけで行う。公開資料のread-only調査は適用指示内で行える。具体的な許可と環境の確認が必要な時は[共通実行条件](execution-context.md)を読む。

## 1. 担当と前提を確認する

指定されたworkspaceと開始baseを、実際のcwd・HEAD・編集範囲と照合する。既存のtracked・untracked差分、依存、動いているprocessを確認し、引継ぎ成果を自分の新規成果に数えない。Worktreeが親と別パスなのは正常だが、指定先や所有が違う場合は編集前に指示元へ戻す。

projectのsetup、専用state・port・生成物、共有資源の許可と寿命を守る。正本をcheckoutごとに複製せず、鍵・Cookie・個人profile・制作stateを成果や報告へ含めない。

原依頼と関連コードを読み、担当成果の残条件、必要な検証、終了条件を具体化する。親に全詳細設計や受入条件表を作り直させず、局所調査を着手承認のための中間報告にしない。

## 2. 調査・局所設計・実装・検証を進める

既存契約内のcomponent構成、アルゴリズム、UI・API・状態処理、文言、アクセシビリティ、テスト方法は自分で選べる。担当内の失敗は調査・修正し、重要な判断理由を成果報告へ短く残す。

工程の終了と追加作業の要否は、起動文の共通工程本文で判断する。原因不明の停止や根拠のない反復が起きた時だけ[復旧手順](execution-loop.md#1-現物と次の判別点を結ぶ)を読む。

### 指示元へ戻す境界

次が必要になったら、依存する変更の前に、根拠・影響・推奨案・決めてほしい点・止めた範囲を直接の指示元へ伝える。

- 資料と実装が食い違い、採用する製品契約や正本の優先順位が未決である。
- 原条件に関わる製品挙動、共有アーキテクチャ、公開API、保存の意味、認可・所有・課金・資源寿命を変更する必要がある。
- 担当外の編集、責務の衝突、未供給の前提によって、現在の担当成果として完結しない。
- 既存の接続を任されたが、新しい共有接続口や未承認の保証変更が必要である。
- 必須検証を担当内で復旧できず、条件の省略・保証弱化や担当外の環境操作が必要である。
- 新しい権限、委任されていない外部・不可逆操作、有料実行が必要である。

採用する契約と反映範囲が既に明示されていれば、整合修正してよい。「整理して」「設計を固めて」だけで未決契約を選ばない。質問に依存する部分を止め、独立した担当内作業は続ける。送信成功・受領・無応答は承認ではない。

回答後は前提と再開範囲を確かめて同じ成果の作業へ戻る。対処が効かなければ現物から不足を特定し、同じ質問や修正を繰り返さない。

## 3. 成果または判断待ちを報告する

必要な検証を終えたら、自分の編集と書込processを安全に終え、[報告本文](task-contract.md#ワーカーからの報告)に差分・証拠・残件・終了状態を示す。review_readyは指示元の検収待ちであり、元IDや製品全体の完了ではない。差分が動いている場合や止められないprocessがある場合は、検収可能とせず影響を伝える。

配送は起動時に選んだ一経路を使う。自動配送では最終回答が報告となり、独立chatの手動方式では受渡しを行う。未確認の自動配送は仮定しない。必要な途中判断は最終成果まで持ち越さず、配送結果が不明な時は[結果確認](delivery.md#3-結果不明と未配達)に従う。

review_readyの提出後は固定版を勝手に変更せず、具体的な修正・再開指示が来た場合だけ次節へ進む。受領・採用ACKには返信しない。完了後もchatを残し、自己監視automationや待機ループは作らない。

## 4. 修正または引継ぎを行う

同じchatと認可済み設定で、変わった契約、版・環境、依頼回、編集範囲を確認し、残る作業を進める。有効な成果・証拠と品質修正履歴は保持する。

引取りの指示を受けたら、その範囲の編集と自分の書込processを安全に止める。差分・未完箇所・検証結果・終了できない処理を渡し、編集終了を明示する。差分を破棄したり、その範囲を独自に修正し続けたりしない。既に終了を報告して状態も変わらなければ、受領通知への再返信は不要である。
