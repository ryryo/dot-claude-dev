# Chatworkの文面を作り、返信・下書き・送信する

ユーザーが指定したチャットと返信先を確認し、依頼された範囲で本文を入力する。このスキルを保存・更新する依頼自体は、Chatworkへの入力や送信の許可にはならない。

## 文面を作る

文案を新しく作るときは、[文体の傾向と参照方法](references/writing-style.md)を読み、[全75例の索引](references/examples-index.md)から今回の場面に近い実例の本文を開く。傾向の要約だけで済ませず、実際の言い回し・長さ・段落の運びを見てから書く。了承・日程、確認・依頼、見積もり・提案、途中・完了報告、訂正・調査の5つの実例集がある。

実例は匿名化された過去の投稿であり、金額・日付・完了報告・設定内容を現在の事実として流用しない。ユーザーが既に採用した本文は、文体を合わせる目的で書き換えず、そのまま扱う。

文章案だけを求められた場合は、このチャットに文面を返す。ブラウザを操作する必要はない。Chatworkへの入力・送信も依頼された場合は、以下の手順へ進む。

## 下書きと送信の区別

- 「文章を作って」は文案の提示まで。「Chatworkに入力して」「返信機能を使って下書きにして」は本文入力まで。「送信は私がします」「送らないで」は未送信で止める。
- 「この文章を送って」など、宛先と本文・用件が明確な送信依頼がある場合に送信する。既に十分な指示があれば、通常の連絡について同じ確認を重ねない。適用される確認ポリシーは守る。
- 既存の下書きがあれば読んでから扱う。今回の本文や返信指定を追記・置換すべきかを判断し、無関係な文章を消さない。

## ブラウザでの操作

ユーザーが指定したブラウザ・タブを優先し、既に開いているChatworkを再利用する。画面操作には `mcp__cua_repl` を使い、最初に返るAPIドキュメントに従う。同じURLへの再移動や再読み込みで下書きを失わない。

### 返信先を設定する

1. チャット名・ルームURLと、対象メッセージの投稿者・日時・本文を照合する。「最後のメッセージ」は実画面で確認する。ユーザーがコメントで特定したメッセージがあれば、その対象を優先する。
2. 対象メッセージの本文をクリックすると、返信・リアクション・引用などのツールバーが現れる。今回確認できた操作では、本文クリック → 最新のAX状態取得 → 対象に現れた「返信」ボタンのクリックで設定できた。
3. **「返信」を選び、「引用」や「AI下書き」と区別する。** 返信後にAX状態を取得し、入力欄の返信指定が対象メッセージを指していることを確認する。

返信指定の表示例：

```text
[返信 aid=<相手のアカウントID> to=<ルームID>-<メッセージID>]相手の名前さん
```

IDや表示形式を手作りせず、実際の返信機能が入力した指定を保持する。過去のAX要素番号・CSSクラス・今回の相手やメッセージIDは再利用しない。

### 本文を入力する

- 返信操作後、入力欄に返信指定が入っている。通常はその末尾へ、ユーザーが採用した本文を貼り付ける。欄全体の置換で返信指定を失わない。
- 複数行は `tab.paste(入力欄の最新AX番号, 本文, { format: "text" })` などの貼り付けを使う。入力後に `getAXState()` で返信指定と本文の両方を確認する。
- 「Enterで送信」の状態を確認する。改行や操作終了のためにReturnを押さず、送信設定も不要に変更しない。

### 下書きで引き渡す場合

返信先・本文が入力欄に残っていることを確認し、送信ボタンは押さない。ユーザーがそのまま操作できるようタブを `markDeliverable()` で残す。入力欄が読める確認画像を保存し、最終回答に画像を埋め込み、「返信として入力済み・未送信」と簡潔に伝える。

### 送信を依頼された場合

送信直前に、対象チャット、返信先、入力欄の全文がユーザーの指示と一致していることを確認する。明示された本文を勝手に変更しない。

画面上の「送信」ボタンを1回クリックし、最新の画面状態を取得する。チャット内に自分の新しい投稿が現れ、本文と返信先が正しいことを確認する。入力欄が空になっただけでは送信完了としない。

タイムアウトなどで結果が不明な場合は、チャット内の投稿と入力欄を確認してから判断する。送信ボタンを繰り返し押して重複投稿しない。確認できない場合は、送信結果が未確認であることを伝える。

完了後は投稿が分かる確認画像を保存して最終回答に埋め込み、送信結果を報告する。
