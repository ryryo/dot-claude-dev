# 文面を作るときの参照方法

この資料は、本人の業務チャットでの文体を、新しい文面に合わせるためのものです。説明を読んだだけで「本人らしい文」を推測せず、今回の用件に近い実例の本文を読んでから書きます。

## 実例から観察できた傾向

以下は、この実例群についての観察です。本人の全発言に共通する規則や、他の相手にも通用する固定テンプレートではありません。

### 用件に合わせて、長さと丁寧さが変わる

「ありがとうございます!」「了解しました！」だけの返答がある一方、引き渡しや見積もりでは数段落にわたって背景も説明しています。短い返答に毎回「お世話になっております」「引き続きよろしくお願いいたします」を付けてはいません。長い提案には「承知しました」「ご確認いただき」など、少し改まった語もあります。A01〜A06・E10・E13・P14〜P16を比較します。

### 先に受け止め、次に自分の動きを置く

「ありがとうございます! 詳細のほう後ほど確認していきますが」「了解しました! 諸々本日返信いたします。」のように、受け止めと次の行動をつなげています。お礼だけで閉じる例もあるため、不要な予定は足しません。A07・A11・A12・A18を参照します。

### 予定は柔らかく述べ、未確認の余地を残す

「進めていければです」「おそらく間に合わせられるかと思います」「ざっとした概算」「〜という感触でいます」などを、詳細確認前の予定や見積もりに使っています。一方、実施した事実は「完了しました!」「確認できました」と言い切っています。柔らかさを真似るために、確定した約束を曖昧にしたり、未確認の予定を約束に変えたりしません。A11〜A14・E01・E06・E08と、A02・P06・P15を比較します。

### 自分の理解を示してから、相手に確認する

「〜ということで良さそうでしょうか?」「〜という理解で良さそうでしょうか?」のように、何をどう理解したかを示します。情報が足りないときは「見逃していたらすいません!」「教えていただけると助かります」と添える例があります。Q03〜Q10・Q14〜Q18を参照します。あらゆる確認に謝罪を付ける傾向だと広げません。

### 状態と、確認した範囲を具体的に書く

「まだ作業中」「ベースの動作するもの」「基本のファイル設置と…部分までだけ確認済み」のように、進んだところと残っているところを一緒に伝えています。完了報告では、テスト送信・転記・メール受信など、確認した動作を並べる例があります。P01〜P04・P09・P14〜P16・C07を参照します。文例の実績を新しい案件の実績として流用しません。

### お詫びは短く、事情・修正・次の動きへつなげる

失念や誤解を認めた後に「今日明日で」「対応します!」「データDL済みです」などが続きます。長い定型のお詫び文にせず、必要な対応が分かる形です。Q13・C01〜C05を参照します。本人にミスがない場面へ、お詫びの文言を足すものではありません。

### 短文は続けて、長文は空行や項目で分ける

短い返答は1〜2文でつながり、長くなると空行、URLを単独の行に置く形、箇条書き、「■」「①」などが出てきます。P07・P14〜P16・E02・E06・E08を参照します。普通の返信を、毎回見出しの多い報告書にしません。

### 丁寧語の中に、日常の言い回しが入る

「ざっと」「とりあえず」「取り急ぎ」「諸々」「〜かなと思います」「〜していければです」「〜になりますかね?」などが見られます。`!` と `！`、`?` と `？` は混在しています。お礼・了承・お詫びに 🙇・🙇‍♂️・🙏 があり、素直な所感に「笑」がある例もあります。A05〜A14・Q14・E06〜E12・P18・C01〜C03を参照します。これらを一通に全部入れたり、普段より多く絵文字を付けたりしません。

## 文案へ反映するとき

1. 相手、直前の用件、今回伝える事実、依頼したいことを確認します。単なるお礼・今後の予定なら、不具合報告や謝罪の実例を混ぜません。
2. 近い実例の語尾だけでなく、文のつなぎ方・長さ・空行・情報の順序を見ます。確認事項がまだないなら、勝手に確認項目を作りません。
3. 今回の内容で書きます。費用・納期・完了・確認済み・権限設定・送信済みなどは、現在の会話で裏付けがあるものに限ります。本人が採用済みの文章や、現在の指定を優先します。
4. 原文の誤記や分かりづらい主述関係までは真似ず、読みやすく整えます。「ですます」の硬さ、絵文字、あいさつを一律に増やして本人らしさを出そうとしません。
5. 文案だけの依頼なら、このチャットへ文面を返します。Chatworkの入力や送信は、それぞれ依頼された場合にだけ行います。

参照した文例番号や分析は、通常の完成文には添えません。文体の説明を求められたときに示します。

## この実例集の作り方と限界

- クラウドOSに保存された業務チャットのうち、2系統・複数月にわたる262投稿を読み、本人アカウントの120投稿を確認しました。相手の引用、タスク編集の通知、添付だけの投稿、削除表示を除き、74投稿から75例を採用しています。
- 本人アカウントでの投稿であることを確認したもので、手書き・AI補助などの作成経路は区別していません。このチャットで今回作成した未送信の文案は、過去の実例に含めていません。
- 会社・個人・案件・店舗・地名・URL・メール・ファイルパス・具体的な金額・日付・特徴的な構成名を、一般的な呼び名や `［参照URL］` などに置換しています。語尾や段落の運びは原文を優先し、一部は話題や機能名も一般化しています。
- 返信先や引用元の表示、添付の実ファイル名は除去しています。採用文のうち明らかな誤記を直した例は、その例に注記しています。元投稿へ戻れるID・リンクや対応表、未加工のログ、認証情報は、このスキルへ保存していません。
- 元の投稿は文体の観察資料であり、費用・納期・運用手順・削除や公開範囲などを現在の判断に使う資料ではありません。

今後増やすときも、本人の本文を原資料で確認してから匿名化します。引用された相手の文章や、新しく生成した例を本人の過去文例として追加しません。未掲載の場面は新規作成の文案として扱い、実例だと偽って補いません。
