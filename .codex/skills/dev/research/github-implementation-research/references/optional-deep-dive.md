# 任意の深掘り

ユーザーが求めた場合、または特定候補の重要な不明点を解消する場合だけ読む。通常の候補発見の完了条件にせず、全候補に一律適用しない。知りたい問いと対象候補を絞り、答えが出た範囲で止める。

## 問いに応じた確認

- **参考にしたい処理があるか**: エントリーポイントから関係ファイルだけを読み、入力・出力、エラー処理、依存環境を確認する。README の記載と、読んだコードから分かる事実を分け、対象の tag/commit とファイル URL を残す。
- **作者の役割や投入の中身**: 関係する設計説明、少数の実質的な commit・PR、レビューの議論を確認する。既存 OSS での主要貢献と、今回の repo への実際の関与は別に示す。初回の大量投入、生成物、vendor、移植元、bot 更新と人の設計・実装変更を区別する。量や commit 数から費やした時間・品質を推定しない。
- **テストが何を支えているか**: 関係するテストの内容と対象、CI の実行結果、既知の制約・Issue を確認する。「テストファイルあり」「CI 成功」「手元で実行済み」は別の事実として記録する。バッジだけから品質を保証しない。
- **現行環境で使えるか**: API・依存バージョン、保守状況、必要な移植範囲、公開利用事例を確認する。archived repo の設計的な価値と、そのまま依存できるかを分ける。
- **コードを取り込めるか**: 採用版の LICENSE・NOTICE・対象ファイルの条件と由来を確認する。表示名や作者の評判だけで判断しない。

クローンや実行が必要なときだけ範囲を絞る。未確認の公開コードを実行する前にスクリプトや依存取得・外部副作用を確認し、適切な隔離環境を使う。調査のための star、fork、Issue・PR 作成等は行わない。

## 追加報告

通常の候補情報に、調べた問い、根拠のファイル・commit・PR・テスト結果の公開 URL、確認範囲と残る不明点だけを足す。読んでいない箇所・実行していない挙動まで結論を広げない。網羅的な監査表やランキングスコアは不要。
