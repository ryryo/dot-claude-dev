# ① ローカルが司令役

対話・方針判断・次工程の指示を手元のCodex / DSHに残し、必要な処理をInstaboxへ渡す。目的は、手元の対話性を保ちながら実行負荷や検証環境を分けること。

## 準備と資料

- 司令役と推論・Session保存の場所、遠隔へ移す処理を明記する。SSH接続があるだけで、司令役までクラウドへ移ったと扱わない。
- [Instabox SSH](https://instabox.sh/docs/ssh) と [CLI](https://instabox.sh/docs/cli) で実行・転送・切断仕様を確認する。対話セッションに結び付く実行と、切り離したジョブを区別する。
- CodexのSSHプロジェクトを使うなら [公式Remote connections](https://learn.chatgpt.com/docs/remote-connections#connect-to-an-ssh-host) を読み、アプリ版・遠隔ランタイム・認証・ゲートウェイとの実接続を確認する。既存DSHや任意CLIの監督まで統合されると仮定しない。
- DSHのSSH providerを使う場合は、[公式リポジトリ](https://github.com/deepseek-ai/deepseek-harness) の利用版のSSH資料を読む。参考となる [0.2.1-rc.2の契約](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.1-rc.2/docs/subsystems/ssh.md) と別版の実装を混同せず、helper・lease・切断時の後片付けも確認する。

## 最小の試行

1. 検証タスクの中から、依存導入・ビルド・テストなど遠隔へ分ける工程を選ぶ。作業先・入力版・成果保存先を対応付ける。
2. ローカルの司令役から実行し、遠隔で処理された証拠と終了コードを回収する。次の判断や修正はローカルが行う。
3. 切断耐性が検証対象なら、他の作業を巻き込まない有限のジョブで接続を切る。再接続し、処理が残ったか・終了したか・後片付けされたかを照合する。
4. 差分・ログ・配布物を回収し、タスクの受入条件を確認する。ローカル不在で次の指示が出なかったことと、遠隔の単一ジョブが継続したことを分けて記録する。

## 観測すること

実行環境の再現性、手元の負荷・待ち時間、転送や環境準備の手間、人間の介入時間、切断後に残った処理、結果回収の確かさを見る。同じタスクをローカルで行った記録がなければ、改善率を実測したとは言わない。

ローカル停止中の継続的な指示・監督が必須なら、この構成単独ではその要件を満たさない。観測結果とともに②または③を次の候補として示し、勝手に移行しない。
