# 実験記録のひな形

既存の実験記録があれば形式を尊重し、以下の判断と証拠を記録する。新しい記録は `experiment.md` など、実験IDと対応するファイルにする。適用しない項目は理由を記し、未実施を成功やゼロへ置き換えない。

```markdown
# Instabox 開発実験 <実験ID>

## 仮説と仮案
- タスク、完了条件:
- 推奨パターン、選定理由、代案を選ばなかった理由:
- 検証したい仮説と成功を判断する観測:
- 未確認の成立条件:
- 司令役・実行・状態保存・再接続UIの場所:

## 試行条件
- 試行ID、日時とタイムゾーン:
- 基点commit、対象範囲、入力・配布物の識別情報:
- 作業機ID、OS、ツール・実行器の版、使用モデル:
- 専用作業先、Session / Goal / ジョブID（使用時のみ）:
- 実効休止・タイムアウト・権限、確認方法:
- 許可操作、時間・試行回数・利用量の上限、停止条件:
- 参照した公式URL、取得日、版、未取得の資料:
- 結果保存先、環境と接続・タイマーの保持方針:

## 観測と証拠
| 時刻 | 場所・工程 | 実行・切断・停止・再開などの事実 | 状態・終了コード | 対応するログ・差分・画面・成果物 |
| --- | --- | --- | --- | --- |

- ローカルを不在にした方法・期間、実際に試した条件:
- 不在中に開始・完了した後続工程と実行側の証拠:
- 復旧時のoperation・既存実行・完了工程の照合（実施時）:
- 認証・承認・上限・レビュー待ち、結果不明などの停止理由:
- 人間の介入時間・内容、現在地を把握する時間:
- 実際の利用量・費用（取得できた範囲）、比較対象と差:

## 成果と結論
- タスク: 完了 / 未完了。受入条件ごとの結果と証拠:
- 試行: 終了 / 中断。終了理由:
- 構成の判定: 今回の条件では有効 / 条件付き / 不適合 / 判定保留
- 判定の根拠、成立条件、観測した範囲:
- 未検証、実施不能、結果不明の項目:
- 次に検証すること・変更する要因:
- 残した環境・待ちジョブ・接続・タイマー、後片付けの結果:
```

認証情報の値、秘密を含む接続文字列、認証ストアは記録に入れない。非公開ログや差分は非公開保存先に置き、共有先には必要な証拠だけを整理して渡す。
