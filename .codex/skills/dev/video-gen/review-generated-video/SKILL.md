# 生成動画のレビュー

動画が要求を満たし、映像として成立しているかを判断する。場面の列挙や文字の網羅をレビューの目的に置き換えない。数値検出と追加画像は判断の補助手段とする。

## 入力から評価条件を決める

対象動画、元プロンプト、参照画像・動画、用途、承認済みの変更を、会話と既存成果物から確認する。人物・商品、主動作、構図、カメラ、場所、尺、演出のうち、今回の必須条件を短く整理する。入力が既にあれば再質問しない。

- プロンプトに書かれた条件と、映像から推測した意図を分ける。プロンプトや参照がなければ、実際に見える品質は確認できるが、要求との一致は未確認にする。
- 参照が顔、衣装、構図、商品形状などのどれを支配するかを区別する。無関係な要素まで同一性の条件にしない。
- 浮遊、変形、ワープ、誇張、非現実的な空間など、指定された演出と許容済みの差異を先に把握する。現実の物理に従わないだけで不合格にしない。
- 複数動画の比較は指定範囲で行う。手法の試験なら代表的な1本から始め、同じ確認を全候補へ自動で繰り返さない。

## 確認の優先順位

| 観点 | 判断すること |
| --- | --- |
| 意図との一致 | 必須の人物・物体・動作・構図・カメラ・演出が実現しているか。主動作を省略していないか |
| 構図・形状 | 被写体、視線、接触箇所、商品構造を用途に必要な大きさで読み取れるか。意図しない形状変化や背景との融合がないか |
| 動作・物理・時間 | 同じショットで形状と存在が保たれ、接触、支持、遮蔽、移動の前後関係が成立しているか。演出内の規則と矛盾するか |
| 用途固有の条件 | ループ境界、固定カメラ、発話と口の同期、実配置での見え方など、指定されたものだけ |
| 必要な文字 | 読ませる日本語、コピー、商品名などが意図どおりか。文字のない映像では非適用。背景の小文字を際限なく追わない |

指・足・容器などの一瞬の見え方は、遮蔽、ブラー、遠近法、編集点でも変わる。単独フレームで変形・消失・不正な接地と断定せず、同じショットの前後を確認する。構図の好みを必須修正へ格上げしない。

## 少ない追加確認で根拠を得る

画像抽出と数値解析には [video-analysis-core](../video-analysis-core/SKILL.md) の同梱CLIを使い、返された画像を実際に閲覧する。観察方法の限界は [映像の確認と証拠](references/evidence.md) に従う。既存の抽出画像・解析・回答を再利用する。

1. 対応する動画入力または実際に映像を確認できる再生手段があれば、全体の流れを確認する。ツールが静止画だけ返す場合は、再生を開始したことを連続視聴の証拠にしない。
2. 画像で扱う場合は、区間の代表画像から構成と評価対象を把握する。全フレームの数値走査と、画像の意味をモデルが全数読むことは別。数値上の区間は意味上のショットとは限らない。
3. 要求との不一致や形状・動作の疑いがある箇所だけ、前後の短い区間を追加確認する。動作の検証には時刻順の近接フレームまたは連続映像を使い、離れた「違う画像」だけで連続性を判断しない。
4. 質問されなかった区間でも未確認の大きな視覚変化が残る場合は、少数の候補を自動で補う。既に見た画像との数値差を使い、文字の存在や既知の正解時刻に依存させない。意味が重複する場合は打ち切る。

最初に追加の画像数・区間数または時間の枠を置く。短尺1本なら、不明点と自動補完をまとめた追加1巡を出発点にできる。固定枚数や実験の閾値を品質保証にしない。残った疑問が採否を変える場合だけ、理由を添えて必要範囲を広げる。網羅確認を依頼されていなければ、軽微な未確認事項は残して終了する。

Lunaなどへ分担する場合は、許可された範囲で画像・時刻・必須条件・確認したい観点を渡す。モデルを自動変更せず、観測の記録と採否の責任を区別する。既存回答を再利用できる補完に、新規セッションで全分析をやり直す必要はない。

## 判定と修正方針

各問題は、時刻、実際に観察した状態、どの要求・映像上の関係と矛盾するか、前後を確認した根拠を一組で記録する。モデルの推測や数値の大きさだけを根拠にしない。

- **採用可能:** 確認した必須条件を満たし、採否を妨げる具体的な問題がない。確認範囲を付け、実際の採用・公開操作とは分ける。
- **修正が必要:** 根拠のある不一致・破綻がある。症状と原因仮説を分け、維持する合格要素と、直す箇所を示す。
- **判断できない:** 重要な条件の入力不足、解像度不足、動きを観察できないなど。未確認を不合格や合格へ置き換えない。

判定は観点ごとに分けてもよい。例えば構図の修正根拠はないが、滑らかさは未確認、という報告にする。根拠がなければ修正指摘0件で終了する。

原因が意図・構図設計なら [generative-prompt-design](../generative-prompt-design/SKILL.md)、H3の表現へ戻す必要があれば [h3-prompt-writing](../h3/h3-prompt-writing/SKILL.md) を必要な場合だけ使う。レビューだけの依頼で再生成、課金、採用状態の変更を開始しない。実行は既存のユーザー承認範囲と担当生成スキルの規約に従う。

## 保存と報告

既定では以下を会話内で報告する。`review.md` などのファイルは、ユーザーがファイル生成・保存を求めた場合だけ作る。その場合は指定先、指定がなければ既存の制作物ディレクトリを使い、元動画を上書きしない。

- 判定と、今回確認した必須条件
- 根拠のある問題だけを時刻付きで記録。0件なら明記
- 必要な修正方針と維持する要素
- 使用した入力、画像・短区間への参照、観察方法と範囲
- 元プロンプト照合、音声、滑らかさなどの未確認事項

解析用の画像と処理状態は既定で一時ディレクトリに置く。元動画・フレーム時刻・抽出条件はそこで管理し、成果物としての永続保存とは分ける。大量の画像、採点表、比較ページは毎回作らない。

## スキルを検証するときだけ

[検証の境界](references/validation.md) を参照する。成功例のレビューを、欠陥を検出できることの証明にしない。
