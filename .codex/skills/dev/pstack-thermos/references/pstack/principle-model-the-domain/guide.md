# 対象の概念を構造で表す

[Codexでの実行規則](../../execution.md)を読んでから使う。

対象の概念をデータ構造へ表し、条件分岐へ分散させない。散らばる真偽値や同期が必要な複数の状態は、状態機械・型付きモデル・判別共用体で表す。

用途に応じて、登録表、対応表、reducer、コマンドとイベント、キュー、キャッシュ、索引、グラフ、正規化した集合を選ぶ。処理の順序（読取・検証・変換・保存）ではなく、所有する知識や不変条件でモジュールを分ける。

合う構造がなければ、禁止すべき状態とデータのアクセス方法から考える。現在の構造が明確で局所的なら抽象化を強制しない。分岐、重複ルール、不正状態、寿命の危険を減らさない間接化は疑う。

新機能のたびにif/elseが増える、同期すべき二つ目の真偽値が増える、段階名のモジュールに同じ概念のルールが繰り返される場合は、構造を見直す。
