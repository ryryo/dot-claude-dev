# 独立案を比較して統合する

[Codexでの実行規則](../../execution.md)を読んでから使う。

作業一覧を「条件設定、案の作成、独立採点、基礎案の選定、統合、検証」に分ける。各案が作る成果を明示し、その課題の成功を3〜6の具体的な基準にする。担当には課題を渡し、採点の都合へ誘導しない。

既定は `poteto-agent` が親のモデルと思考量を継承する。モデル比較を依頼された場合だけ、実際に利用できる組合せを設定する。不足する案を黙って差し替えず、範囲の不足として記録する。同じモデルの独立実行をモデルの多様性と呼ばない。

各案に別のWorktreeまたは `/tmp/arena-<slug>/candidate-<n>/` を割り当てる。同じ課題、共通資料の所在、専有する出力先、成果と検討・却下した代案を示す指示を渡す。並列上限内で実行し、必要なら回ごとに回収して進める。出力のない担当は不足として記録する。

全案の作成が終わってから、独立した読み取り専用の採点担当へ基準と案のパスを渡す。採点は親が全案を読む作業と並行できるが、案の作成中には始めない。

親は全案を最後まで読み、基準ごとに採点する。独立採点と異なる場合は両者の理由を読む。次の保守担当が不変条件を保って拡張しやすい案を選び、同等なら小さいAPIと明確な境界を優先する。

他の各案を再度読み、有用な部分を基礎案に合わせて統合する。機械的に貼り合わせず、一貫した構成にする。案が同じ形へ収束したなら合意した形を採用し、統合を強制しない。大きく食い違うなら課題を定め直して再実行する。

統合した成果を実際に検証する。条件が違っていたなら条件設定へ、見落とした有用案があれば統合へ戻る。基礎案、取り込んだ内容と出典、却下理由、不足、検証結果を短い記録と成果に残す。
