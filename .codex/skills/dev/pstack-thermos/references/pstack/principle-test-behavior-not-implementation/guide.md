# 利用者が見る動作をテストする

[Codexでの実行規則](../../execution.md)を読んでから使う。

利用者と同じ呼び方で対象を実行し、観測する結果を具体的な期待値と比較する。呼出回数だけや定数の言い直しでは動作を検査できない。

取り込んだすべての関数が `undefined` を返しても合格するなら、検査を書き直すか削除する。弱い存在確認だけ、モック呼出・不在だけ、対象自身から作る期待値、設定・プロンプトの文字列を固定する検査、fixture自身を検査して対象を実行しないテストを見直す。

テスト本文で具体的な入力を渡し、文字どおりの期待値または観測可能な副作用を検査する。不在を検査するなら別の入力で存在も確認する。定数はそれを読む仕組みの動作、モックは渡された内容や処理後の状態を検査する。

表同士のキーや親子関係などの整合性検査と、`*.test-d.ts` の型検査は保持する。
