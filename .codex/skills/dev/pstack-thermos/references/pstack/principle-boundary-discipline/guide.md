# 境界で検証する

[Codexでの実行規則](../../execution.md)を読んでから使う。

検証、型の絞り込み、エラー処理をシステム境界に集める。設定は解析時に検査し、生データを対象の概念を表す型へ変換する。内部では型を信頼してエラーを伝播し、既に検査した値へ同じ検証やnil検査を重ねない。

公開するのは対象の概念であり、通信・保存・フレームワークの内部表現ではない。一般的な仕組みは内部へ、用途固有の方針は境界へ置く。

業務処理はフレームワークに依存しない純粋関数にする。解析は生バイトから型付き状態、プロンプト作成は構造化状態から文字列、採点は状態から結果への変換として扱う。外側の接続処理は薄く機械的にする。

今の入力が実際にシステム境界を越えているか、外側が呼ぶだけの純粋関数にできるかを確かめる。重複検証は安全性の証拠にならない。

例えばHTTPで受けたJSONは入口でschemaに照合し、その後の計算は検証済みのドメイン型を受け取る。
