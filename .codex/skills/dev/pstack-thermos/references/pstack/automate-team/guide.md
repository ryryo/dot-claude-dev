# チームの規範を根拠から抽出する

[Codexでの実行規則](../../execution.md)を読んでから使う。

先に `automate-maintainer` を読む。この手順は対象repoと人の一覧を決め、収集・個人への帰属・統合・制作・評価はそちらを使う。二重の収集手順を作らない。

URLまたは `owner/repo`、指定がなければ現在のremoteから対象を確定する。複数remoteの意図が不明なら確認する。既定は12か月。複数repoは所有と公開範囲を別に記録する。認証された接続でrepo・公開範囲・既定ブランチを確認し、リンク先を収集範囲の追加許可とみなさない。

CODEOWNERS、メンテナー一覧、統治・貢献資料と、期間中の実質的な著作・採用済みPR・他者PRのレビュー・設計議論・Issue整理・リリース判断を照合する。ページを送り、検索上限があれば期間を分割し不足を記録する。生涯コミット順位、星、フォロワー、組織所属、CODEOWNERSだけで現在の中核担当としない。

各人の宣言上の役割、現在の担当領域、根拠URL、採用理由を一覧にする。活動の少ない専門領域の担当も含め、非活動の宣言担当と不確かな候補は別に示す。根拠のある人は進め、本人の同定・範囲・不確かな選定・収集規模に必要な確認だけを行う。「全中核担当」を上位数人へ黙って縮めない。大規模なら区切って処理し全員の状態を残す。上限で止まれば未処理の人を具体的に示す。

一覧、repo、期間、所有の証拠、出力先、不足を `automate-maintainer` へ渡す。既定は `<repo>-team-mode` と個人別の参照証拠。個別モードも必要な場合だけ作る。人別に収集し、共通規範・根拠のある所有・相違を維持する。全員一致や活動量による優先を作らない。

`skill-creator` と評価手順で検査し、人・出典の網羅性と不足を報告する。更新は前回締切と現在の所有を比較し、参加・離脱・非活動・新しい規範・反例を再評価して新しい締切を残す。モード作成だけで自律チーム、本人としての発言、定期収集を起動しない。
