# 繰り返す修正を仕組みにする

[Codexでの実行規則](../../execution.md)を読んでから使う。

同じ指示を二度書こうとしたら、lint、設定値、実行時検査、スクリプトで強制できるか確かめる。可能なら仕組みにして、その指示文を除く。判断が必要なら、指示を見つけやすくし失敗例を添える。

複数の方法があれば、状況で使える最も強い方法を選ぶ。不正な状態を構築できない型、CIで失敗するlintや禁止API、共通の補助処理、実行時検査の順に考える。周囲のコードが次の担当のひな型になるため、弱い対処を増やさない。

訂正やテスト失敗を一回限りか繰り返す傾向かに分け、一回限りは作業メモ、反復はスキルやlint、システム全体の問題は原則へ対応させる。記録だけで終わらず、許可範囲で適用するか具体的な作業にする。

「覚えておく」だけ、記録するだけ、一例だけ直して同じ傾向を残す対応を避ける。構造で防げる訂正はその仕組みに集約する。
