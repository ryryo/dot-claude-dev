# 読み手が補う知識を減らす

[Codexでの実行規則](../../execution.md)を読んでから使う。

読み手が頭の中で保持しなければならない状態と、問いから答えへ到達するための層を数える。呼び出し元が一つだけの転送用ラッパーをまとめ、変更可能な状態の範囲を狭くする。

関連する判断とデータを近くへ置く。明示的な名前と直線的な処理を選ぶ。文字数を短くしても、暗黙の知識や戻り読みが増えるなら簡単になっていない。

責務や不変条件を隠す有用な境界は維持する。抽象化が読み手の必要知識を減らすか、単に別ファイルへ移すだけかで判断する。

純粋関数と返り値を変更より優先し、ローカル変数、フィールド、モジュール状態、globalの順で状態を狭くする。同期するより導出する。不変条件は境界で一度説明する。隣接する層が同じ引数と操作を転送するだけなら統合する。新しい読者が30秒以内に「値の取得元」と「変更できる主体」を答えられるか確認する。
