# 最小の変更で必要な成果を得る

[Codexでの実行規則](../../execution.md)を読んでから使う。

少ないコードと複雑さで必要な成果を得る。改善やリファクタリングでは、追加より先に削除できるものを探す。

呼び出し階層を浅くする。大きな処理を隠す有用なインターフェースは、単なる深い呼び出し連鎖とは違う。問いに答えるため3つを超えるファイルや層を追う必要があるなら、平坦化を検討する。

同じ判断を複数箇所に置かず、一つの取得元で決めて単純な結果を渡す。型、スキーマ、パイプラインへ新しい信号を渡す前に、より直接的な経路を探す。単なる転送、表現の漏れ、重複した判断を小さいうちに除く。

問題を完全に解決する最小の差分を選ぶ。見た目の洗練だけの定型コードを増やさない。保守する人が理解し続けるのに疲れる設計は見直す。
