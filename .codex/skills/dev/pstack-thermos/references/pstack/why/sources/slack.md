# 会話の調査

設計の得失、障害中の判断、reviewerへの回答、顧客要望、採用後の見直しを探す。接続のschemaと認証を先に確認し、認証失敗なら未調査を報告する。投稿はしない。

作者とPR採用前後の期間、機能名、シンボル、表記ゆれ、PR URLや `/pull/<number>`、エラー文字列、関連チャンネルで探す。関係するメッセージはthread全文を読む。`#eng-*`、`#proj-*`、`#incident-*`、`#sev-*` などは例であり存在を確認する。

保持期間、検索できないDM、冗談を判断にする誤り、一文だけの文脈欠落、認証不足を区別する。各threadのチャンネル、permalinkまたはID、参加者、期間、帰属付きの短い引用、議論の背景を返す。
