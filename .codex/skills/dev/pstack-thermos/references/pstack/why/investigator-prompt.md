# 理由の調査担当への指示

担当する資料の手順を [索引](source-playbook.md)から一つ付ける。防御的なコードには障害履歴の観点も付ける。読み取り専用で証拠を集め、結論の物語を先に作らない。

広く探してから絞る。PR、チケット、資料、会話は本文・コメント・下位項目を最後まで読む。担当する種類のリンクは追い、別種類の資料への参照は追加の手がかりへ残して親へ渡す。同じ資料を重複して調べない。

言い方が重要な箇所は正確に短く引用し、URL、ID、hash、file:line、作者、日付を付ける。引用の利用条件を守る。検索した語と範囲も記録する。反証になるものを優先して残し、現在の解釈が誤りでも同じ証拠が見つかるかを問う。部分的な発見を完全な証拠へ膨らませない。

動作の変更と理由を区別する。`limit = 50` から `100` への変更だけでは理由が分からない。コードの様式から作者の意図を決めない。別の機能の証拠で対象の問いを代用しない。

## 報告

- 調べた資料の種類。
- 検索した語、範囲、開いた項目。
- 直接の証拠。引用、場所、作者、日付、問いとの関係。
- 間接の証拠。内容、場所、推論の鎖、別の読み。
- 矛盾。両方の引用。
- 欠落。何をどこで探し、何が見つからなかったか。
- 別資料へ渡す手がかり。

最終回答は書かず、矛盾の側を選ばず、証拠を超えて推測しない。
