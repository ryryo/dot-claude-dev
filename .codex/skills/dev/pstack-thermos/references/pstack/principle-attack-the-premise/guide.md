# 共有する前提を疑う

[Codexでの実行規則](../../execution.md)を読んでから使う。

同じ前提を共有する修正が2回以上失敗したら、修正方法より前提を疑う。失敗はその前提についての証拠になる。

失敗したすべての修正が仮定した内容を一文にする。次の修正前に、主体ごとに偏りを数える再実行可能なスクリプトを作る。全体量だけでなく、どの主体に偏りがあるかを見る。同じ少数の主体に毎回偏るなら、その役割を割り当てる仕組みを調べる。

補償処理を加える前に非対称な割当を除く。役割の交代・無作為化・移動を検討する。戻し経路、共有プール、一括受渡し、定期再配分だけでは、割当を残して毎回の処理を増やす場合がある。

前提の記述と主体別計測ができるまで次の修正を始めない。偏りが均等なら、その前提が原因だと決めず別の原因を調べ、計測を証拠として保持する。

`principle-build-the-lever`、`principle-fix-root-causes`、`principle-laziness-protocol`を参照する。新要件で設計を組み直す `principle-redesign-from-first-principles` と、現在の仮定を疑うこの手順は区別する。
