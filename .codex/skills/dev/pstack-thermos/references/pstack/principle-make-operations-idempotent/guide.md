# 再実行で同じ状態へ収束させる

[Codexでの実行規則](../../execution.md)を読んでから使う。

一部が既に実行済みでも、繰り返すと同じ目的の状態へ収束する操作を設計する。再試行や障害復旧のたびに重複や破損を増やさない。

作成前に存在を確認し、既存の正しい状態を保持する。安定した識別子、upsert、原子的な状態変更、重複排除のキーを必要な境界で使う。「必ず一回だけ実行される」を前提にしない。

初回、再実行、途中失敗後の再実行を確認する。再実行時に既存の利用者データを消して初期化する方法を、冪等性と呼ばない。

起動は既存状態の照合、古い資源の整理、生きているセッションの引継ぎで収束させる。整理は作成順でなく内容の同等性を使う。ロックはPIDによる古い所有の検出、繰り返す実行は失敗の再起動と各回の新しい入力の生成を検討する。あらゆる途中で失敗しても同じ状態へ収束するか確かめる。残された状態次第で結果が違うなら照合・修復の段階を設ける。

例えば同じ依頼IDで再実行する保存処理では、二回目に別のrecordを作らず、既存の結果を返す。
