# 自律実行で完了条件まで進める

1. 最初の反復前に、テスト合格、再現の解消、対象PRの採用、画面差ゼロ等、確認できる終了条件を定める。
2. 現在のセッションで使えるイベント監視を使う。後の無人実行には利用者の明示依頼と対応する永続的な実行機能が要る。なければ中間成果と機能不足を報告する。再起動の約束や長いsleepで代用しない。
3. 各反復で証拠が正当化する最小変更を行い、条件に対して検証する。進んだ変更は許可範囲で保存し、効果のない変更は自分の差分だけ撤回する。「役に立つかも」という防御を残さない。各単位を確認してから次へ進む。
4. 作業中のスキル故障、関連不具合、flakyな検査、レビューの誤指摘、ツールの故障、残った作業、修復可能なずれは許可範囲で対処する。主条件へ戻り、別の修正は別の変更にする。可逆作業を不要に利用者待ちにせず、不可逆操作、実験で決められない製品判断、実際の行き詰まりだけ明示する。
5. `show-me-your-work` で各反復の変更と条件の変化を記録する。
6. 条件を満たしたら終了する。停滞だけで止めず方法を変えるが、本当の行き詰まりでは不足を示す。成功と報告するため条件を緩めない。

終了条件、反復数、採用した成果、撤回したもの、最終の条件判定を返す。

コード変更のレビューは [レビューの進行](../../../review.md)へ進む。計画・設計の反証と、実動作・性能の検証は、それぞれの対象に応じて行う。
