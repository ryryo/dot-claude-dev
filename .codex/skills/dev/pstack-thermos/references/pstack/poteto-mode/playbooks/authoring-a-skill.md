### スキルの作成・修正

スキルの文体と判断基準を担当する。

1. ホストで使えるスキル作成支援を読む。Codexでは `skill-creator`、Cursorでは `create-skill` を使う。存在を確認せず名前だけ呼び出さない。
2. frontmatterの `name` と `description`、参照先の存在、スキル間リンクを検証する。
3. 構造や実行動作を変える場合は意味のあるケースで確認する。主観的な文体修正だけならテストを追加しない。
4. PRが依頼範囲に含まれる場合は [PR作成](opening-a-pr.md)へ進む。

迷った文は、判断を変えるかで残すか決める。動作を直接指示し、理由がないと誤解する規則だけ説明する。型、README、設定など構造上の正本を参照する。別スキルの指示を繰り返さず、パスで委ねる。繰り返し必要になる手順に適切な置き場がなければ新しいスキルを提案する。

返答には目的、主要な設計判断、検証結果を示す。
