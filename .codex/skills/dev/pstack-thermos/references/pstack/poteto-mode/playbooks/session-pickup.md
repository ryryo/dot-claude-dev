### 作業の再開

既存の記録から再開点を特定する。

1. 現在の会話、明示された以前の実行、判断ログ、push済みブランチ、対象実行のTraceDecay記録から探す。メタデータと最近の判断を先に読む。非公開セッションの保存領域を横断検索しない。長い指定記録は許可された読み取り担当か要約で扱い、ファイルとrevisionの参照を残す。履歴がなければ制約を明記してリポジトリの証拠から復元する。
2. ブランチ、worktree、採用済み変更、未完todo、決定事項を復元する。既存の記録を入力として尊重し、完了した調査をやり直さない。
3. 計画と採用済み成果を比較し、完了と残件を分けて再開点を示す。
4. 継続、完成した提案の提出、以前の結論の採否、失敗分析のどれかを選び、適切な手順へ渡す。
5. 引き継いだ主張は元の目的と実成果物へ照合する。以前の自己申告だけで証明済みとは扱わない。新しい差分や不足の確認に限定する。

返答には停止点、引き継いだ内容、再確認した内容、再開点、結果を示す。
