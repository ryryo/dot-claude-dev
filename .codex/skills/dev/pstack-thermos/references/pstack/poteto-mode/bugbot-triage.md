# 自動レビューの指摘を扱う

[PR監視](playbooks/babysit.md)で各threadを分類する。全コメントを必須修正にしないが、自動で無視もしない。

- `fix`。正しさ、セキュリティ、privacy、損失、認証、料金、移行、冪等、race、公開された動作の実問題。原因を持つ最下段のPRで修正する。外部返信が許可されていればcommit SHAを返して解決する。
- `dismiss`。記録された狭い低リスクの誤検知で、現コードが問題を否定する。根拠を短く示す。
- `ask`。調べても解決しない重大な判断や曖昧な製品判断。証拠と選択肢をそろえて本人へ尋ねる。可逆で明確な修正は既存の許可範囲で進める。

新規・重大・セキュリティ・データ関連は、過去の類例だけで退けない。履歴上の本人の判断を全員向けの免除規則にしない。

## 学習したパターン

題名、確信度 `candidate | recurring | strong`、退けられる条件、退けてはいけない境界、検出する文言・コード、出典URLまたは履歴を記す。一、二例はcandidate、複数の実照合でrecurring、狭く低リスクで繰り返し確かめたものだけstrong。

| 候補 | 退けられる条件 | 退けない条件 |
|---|---|---|
| 意図した見た目の変更 | PR・画像・設計確認で明示済みの共有見た目だけの指摘 | アクセシビリティ、focus、keyboard、contrast、API契約 |
| 上段の利用 | activeなPR一覧とdiffで後続利用を確認できる | 単独PR、public API、未確認の利用 |
| 移行中の小さい重複 | 削除予定の旧経路と意図的に並行させる局所処理 | security、料金、データ、API、長期的な共有部品の実益 |
| 既存の不変条件 | 型、共有component、framework、正本で保証済み | 仮定だけ、時間依存、非同期や状態のずれ |
| 本人が指定した後続 | 既知の低リスクで、このPRが悪化させない | 新しい回帰、中・高重大度、本人判断なし |
| 撤回済み・誤検知 | bot自身の撤回とローカルの規則確認 | 根拠なしの「誤検知」、高リスク |

上表は候補であり、一律のskip規則ではない。撤回の類例のみ基点でrecurringとされている。由来はHashemKhalifa版の同じ参照パス。

## 特に検証する候補

- ブラウザ標準のsticky、scroll、paintをJSの複製や転送・maskへ置き換えたコードはほぼ退けない。`deltaMode`、touch、端のscroll連鎖、tap判定、hit-test、observerとReactのタイミングを確かめる。基点の一PRでは六回・約十八件を修正している。
- 文章とテストの契約ずれは、PR tipでそのテストを先に実行する。赤なら確認済み、緑なら退ける実証になる。以前の修正回数から推測しない。基点の一PRでは八回中の七回目に実際のずれが見つかった。
- 古いsecurityレビューなら、現在tipに正確な認可・検証が副作用の前にあり、該当する主体のテストがあるか確認する。no-op、実行順の誤り、未検証なら退けない。
- `ENOENT` のfallbackを全失敗へ広げる提案は、依存がない場合と命令が実行され失敗した場合の違いを検討する。元のエラーを隠さない。同じ種類の `EACCES` 等の欠落、部分状態・損失、冪等かつ元エラーを保持する再試行は別に調べる。

各例は上流の過去観察であり、このリポジトリで再現済みの証拠ではない。
