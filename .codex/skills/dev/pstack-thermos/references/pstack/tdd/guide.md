# 失敗する再現から修正する

[Codexでの実行規則](../../execution.md)を読んでから使う。

正しい動作、現在の動作、影響経路、最小の観測できる再現を理解する。既存の単体・component・結合・回帰検査から最も近い小さい検査を選び、意図した動作を表すテストを先に書く。

実装を変える前に実行し、意図した理由で失敗することを確認する。既に合格するか別理由で失敗するなら、実装ではなく再現・テストを直す。近くの仕様を保持する最小の変更を行い、同じ検査が合格することを確かめる。

広い基盤、壊れやすいモック、遅いE2E、本番専用状態、不明確な再現、大きい無関係なfixture変更が必要なら、新しいテストを強制しない。限定スクリプト、操作コマンド、ブラウザ操作、snapshot比較、ログ、結合検査など最も近い有用な確認を使う。

誤った実装に合わせてテストを変更せず、正しい理由なく既存assertを弱めない。対象を絞り、flakyなら可能な限り決定的にして観測する信号を記す。広い故障の種類が見つかっても、まず限定した回帰経路を完成させる。

修正前の検査と実際の失敗、修正後の合格と周辺の確認を報告する。修正前の失敗を示せなければ、理由と代わりの回帰確認を明示する。
