# 独立した担当を分担して回収する

[Codexでの実行規則](../../execution.md)を読んでから使う。

作業一覧を条件設定、委譲、統合、報告に分ける。完了を判定する条件と必要な成果物を示す。範囲分割、同じ課題の競争、両方を混ぜる形から選ぶ。競争では `first pass`、`rank all`、`best-of` を起動前に決める。

Nは全担当数であり同時実行上限ではない。既定は親のモデルと思考量を継承する。モデル比較は現在提供される組合せだけを使い、拒否された指定を架空のモデルへ置き換えない。書き手ごとに出力を分ける。コミットの検証には正確なSHA、測定には回数・一試料の意味・順序を依頼と結果に残す。

実際のCodexツールで `poteto-agent` を起動し、上限内の回ごとに回収してから次を出す。CursorのTask指定や専用VMを仮定しない。既定以外のブランチは指定SHAの隔離Worktreeを準備する。読み取り担当も出力と状態を持つ実行資源は分ける。

依頼は単独で理解できるよう、目標、範囲、担当、検証、報告内容を含める。結果は証拠を付けて `PASS`・`ISSUES`・`BLOCKED` とし、証明できる問題を最初の一件だけでなく列挙する。

SHAや測定法が抜けた結果は採用せず、その担当を一回だけ再実行する。再度抜けたら未確認とする。担当が脱落したら残りを回収し不足を示す。網羅性が必要なら各必須範囲に結果が要る。不足を合格に数えない。競争は先に決めた選択方法で判定する。

生の報告を貼り付けず、結果表、根拠を付けた問題、未確認と脱落、使った選択規則を一つの報告にまとめる。
