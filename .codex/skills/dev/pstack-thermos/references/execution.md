# 実行条件

利用者の依頼、実行環境の制約、リポジトリの `AGENTS.md` に従う。内部手順に操作が書かれていることだけで、その操作を許可済みと判断しない。

## 利用できる機能を使う

サブエージェントは、利用者または適用される指示で委譲が認められている場合に使う。禁止されていれば主担当が進める。並列数、モデル、思考量は現在の環境とリポジトリの規則に合わせる。専用担当の名前を、利用可能な一覧で確認せず指定しない。

同梱の手順は `references/pstack/<name>/guide.md` と `references/thermos/` にある。旧来のスラッシュコマンドや別スキルへの呼び出しは、該当する内部手順を読んで実施する。別の同名スキルへ黙って切り替えない。

ブラウザ・画面操作、Git、検索、作業継続には対象に合う実際の工具を使う。存在しない工具の実行、Plan modeの変更、担当の起動、検証成功を文章だけで装わない。

## 操作の権限

「完了まで」「自律的に」という依頼には継続して取り組む。許可範囲の可逆作業で不要な再確認を挟まない。PR作成、マージ、強制push、公開、デプロイ、外部への送信、取引、定期実行は、対応する依頼・権限・環境の条件を満たした範囲で行う。

未確定の変更があるチェックアウトへの上書き、無関係な変更の破棄をしない。共有する作業場所の規則を確認し、分離が必要な場合は実際に用意してから担当へ渡す。

レビュー担当は対象を編集せず、新たな担当を起動しない。親が指摘を検証し、採用・修正・再検証を判断する。レビュー依頼だけなら指摘を返して終了する。

## 外部サービスと継続実行

Graphite、Bugbot、TraceDecayなどは任意の外部依存。利用できるGit・検索・レビュー経路で同じ目的を満たすか、不足する証拠を明示する。会話の検索には許可された機能を使い、端末の非公開データベースを直接走査しない。

後での監視・再実行は利用者の依頼と永続的な実行機能がある場合に設定する。現在のチャットでの継続と、将来も動く自動実行を区別する。

## 証拠の扱い

実装、検証、配置、実行の有効化、実際の結果、操作権限を区別する。テストの成功を実動作や性能の確認に読み替えず、必要な証拠を得られなければ具体的な不足を残す。上流の過去の記録は、現在の環境の合格証拠にしない。
