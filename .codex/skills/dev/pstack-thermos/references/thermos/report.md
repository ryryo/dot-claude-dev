# 報告と判定

指摘は今回の対象と結び付け、根拠のあるものを優先する。主担当が、正しさ・安全性と構造・保守性の両方を確認して一つの結果へまとめる。

## 指摘に添える内容

各指摘に、短い問題名、重大度、ファイルと行、失敗する具体的な入力・状態・操作順、影響、確認した根拠、最小の検証方法を添える。保守性の指摘には、変更時の負担や複雑さが増える理由と、挙動を保つ再構成案を示す。

重大度は実際の影響から決める。

- `high`：重大な機能破損、情報漏えい、権限の回避、データ損失など。
- `medium`：採用前の修正が必要な動作不良や、具体的な負担を増やす構造上の問題。
- `low`：影響が限定された保守上の問題や、任意の改善。

調査で確認できた問題と、アクセス不足で確かめられない疑問を分ける。指摘なしとするために証拠不足を消したり、可能性だけでhighにしたりしない。既存のPRコメントから取り込んだ指摘は出典を明記する。

## 統合した結果

| 判定 | 条件 |
| --- | --- |
| `REVIEW_CLEAN` | 必要な範囲を二方向とも確認し、未解決のhigh・mediumがない。lowや任意提案は明示する。 |
| `FINDINGS` | 根拠のあるhigh・mediumが残る。不足する確認があれば、その不足も併記する。 |
| `INCONCLUSIVE` | 必要な対象・証拠・観点の確認が不足し、合格を判断できない。 |

結論を1〜3文で示し、続いて重大度順の指摘、必要なら未確認事項を返す。レビューの方法も「独立した二担当・並列」「独立した二担当・順次」「主担当による二方向確認」のいずれかで示す。必須の独立検収が未実施なら、その不足を判定へ反映する。

合格は確認した対象と条件に限る。実動作・性能・CI・マージ条件はそれぞれの証拠で判断する。外部投稿や採用の操作権限は、この判定に含まれない。
