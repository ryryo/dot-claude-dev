# アドバイザーレビュー

移植の設計と完了判定を、主担当とは別のエージェントがread-onlyで確認する。主担当の要約を追認する工程にせず、旧実装・契約・新実装・検証根拠を直接辿って、欠落や誤った前提を指摘する。設計時と最終確認は同じアドバイザーを再利用できるが、実装者自身の自己レビューは独立レビューに数えない。

## 実施する時点と入力

| 時点 | 渡す資料 | レビュー対象 |
| --- | --- | --- |
| 実装前の設計 | 利用者の依頼・合意、対象/対象外、既知事例、旧実装の版・入口・関連定義、要件対応、現状と移植先の設計、検証計画 | 要件の取りこぼし、根拠のない範囲縮小・仕様変更、旧新の条件別対応、対象全体の構造判断、必要な検証で欠落を検出できるか |
| 統合後の完了判定 | 上記と最新の変更ファイル/差分、実装先、テスト結果、GUIの比較・途中状態の証拠、設計変更と残件 | 実経路と契約、不要な状態/依存/処理が除去されたか、設計との差、確認結果の過大解釈、修正が他の入口や状態へ及ぼす影響 |

読むべき範囲と参照先を絞り、原資料へ到達できる状態で渡す。主担当が期待する結論は指定しない。既存の要件表も監査対象であり、そこに載った項目だけでレビュー範囲を閉じない。GUIの証拠が足りなければ追加比較を求めるか、利用可能なブラウザーで独立確認する。未確認を推測で合格にしない。

複数段階の操作については、原コードの入口から確認・待機・継続・失敗/復旧までを辿り、対象の固定と実行条件の再評価、継続処理の寿命を確認する。要件表に載った既知の競合だけを追認せず、未記載の境界も探す。最終時は、途中で前提が変わった証拠と、その後の表示・保存・履歴等が期待どおりかを確認する。

調査・設計のみの依頼では設計レビューだけを行う。移植途中の是正も、今の対象全体の設計を確認してから修正に進み、最後に影響範囲をレビューする。設計の前提・契約・所有者が途中で変わったら、依存する実装を進める前に、その変更が届く部分の設計を再レビューする。

## 責務と返却内容

- アドバイザーは製品コードや資料を編集せず、仕様を独断で変えない。追加の委譲、外部送信、サービス設定変更へ広げない。
- 指摘ごとに、原資料の箇所、条件と期待結果、実際の差、利用動作/構造への影響、必須是正か任意提案かを示す。確認できない場合は、不足資料と影響を示す。
- 主担当は指摘を再現・照合し、採用/不採用/要判断と根拠を既存記録へ残す。アドバイザーの意見だけを仕様変更の承認にはしない。必須指摘を解消する修正・検証を進め、アドバイザーに変更の影響範囲を再確認させる。
- 必須指摘とは、合意した対象内の欠落・不具合、必要な構造改善の未達、必須検証の不足。任意提案の全件採用は要求しない。根拠のある必須指摘を主担当の判断だけで閉じず、解消または対象/契約に照らした不採用理由をアドバイザーにも確認させる。製品判断が必要な不一致は利用者へ戻す。
- 結果は「確認した範囲・根拠」「必須指摘と対応」「未確認・残件」「設計を実装へ進められるか、または移植完了を判定できるか」を返す。新しい根拠がない合格範囲の全面再レビューや、形式のための別台帳は増やさない。

## 利用制約と未実施の扱い

現在のユーザー指示・適用されるプロジェクト規則・実行環境の制約を守る。レビューの許可を得ている場合は繰り返し許可を求めない。利用できない場合は、禁止・利用不可の具体的な理由と未実施のレビューを明示し、依存しない許可済みの調査・再現・検証は続ける。

レビュー未実施の設計を検収済みとして実装へ進めたり、独立レビュー済みとして完了扱いにしたりしない。利用者が明示的に当該レビューを免除した場合は、その範囲と主担当による代替確認を記録する。免除があっても動作・構造・検証の必須条件は維持し、自己確認を独立レビューと呼ばない。
