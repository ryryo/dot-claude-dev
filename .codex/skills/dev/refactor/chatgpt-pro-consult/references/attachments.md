# 相談資料のZIP準備・添付と返却ファイルの確認

ZIPを準備・添付するとき、または返却ZIPや取得失敗を扱うときに、該当する節だけ読む。GitHubのみの参照や、返却ファイルのない回答回収には不要である。送信範囲は呼出元の許可を引き継ぎ、資料や送信先を広げない。

## 1. 判断に必要なZIPを作る

必要なファイルを選んで専用の作業ディレクトリへコピーする。リポジトリ全体を無条件に圧縮しない。

- 入口の説明、合意済み仕様、関連コードと呼出元・依存先、型/API/DB契約、依存バージョン、関連テストを含める。バグ調査には再現手順、期待と実際、環境、必要な匿名化ログ、設計検討には利用シナリオ、失敗時の動作、既知の制約も含める。
- 比較対象は`current/`、`baseline/`などの相対パスで分け、変更対象と読取専用の比較基準を説明する。抜粋には元の相対パス・行範囲・省略部分を記す。
- Gitの基点commitと未コミット変更の有無を記録する。現在の作業内容が対象ならそれを収録し、HEADだけを渡して現在の状態と称さない。
- `README.md`へ読む順序、収録範囲、正本、未収録の参照先、既知の不足、検証済み・未実施を記す。ChatGPTがローカルパスや非公開リンクの先まで読めるとは仮定しない。
- 認証情報、実値入り`.env`、Cookie、個人情報、顧客データは除き、必要な再現データを匿名化する。`.git`、依存ライブラリ、キャッシュ、無関係な生成物・巨大メディアは含めない。必要な生成SQLや検証結果は目的を説明して含める。

[build_bundle.py](../scripts/build_bundle.py)は標準ライブラリだけで、列挙したファイルのZIPと、サイズ・SHA-256を持つ`BUNDLE-MANIFEST.json`を作る。シンボリックリンク、範囲外パス、代表的な秘密ファイル名を拒否するが、内容の秘密検査は代替しない。

```bash
python3 <skill-dir>/scripts/build_bundle.py \
  --root <staging-directory> \
  --files <reviewed-file-list.txt> \
  --output <private-output-directory>/context.zip
```

一覧はUTF-8で1行1ファイル、rootからの相対パスとし、ディレクトリやglobを指定しない。出力ZIPはrootの外へ置く。内容一覧と本文を確認し、機密の混入・不足・古い版を点検してから添付する。送信用依頼文とZIPのSHA-256も手元に残す。

## 2. ZIPを添付する

添付前に`agent.documentation.get("file-uploads")`を読む。対応するfile chooser経路を使い、chooser待機を登録してから実際の添付入力または対応ボタンを押す。chooserの`setFiles([absoluteZipPath])`で指定し、通常のPlaywrightにあるAPIを推測して呼ばない。

意図したZIP名が添付欄に表示され、進捗表示が消えて送信可能になったことを確認する。ここでは送信せず、呼出元の共通送信手順へ戻る。ZIPのみ・GitHubとの併用で送信手順を分けない。

添付できなければ、必要な文脈を保ってZIPを縮小・分割する。ZIP自体を読めないと返された場合は、収録ファイルを個別添付できるか確認する。いずれも送信範囲を広げない。

### ファイル選択に失敗した場合

古いchooser待機や要素参照を再利用せず、同じ会話を開いた状態で次の順にやり直す。

1. `agent.documentation.get("file-uploads")`を読み直し、入力欄の「ファイルなどを追加」を`press("Enter")`で開く。
2. 「写真やファイルを追加」に対応するボタンを押す前に、`waitForEvent("filechooser")`を登録する。選んだ後ではない。
3. chooser待機とクリックを`Promise.allSettled`で同時に実行し、成功したchooserへ`setFiles([absoluteZipPath])`を一度だけ渡す。タイムアウトを未処理Promiseのまま残さない。
4. AX/DOMでファイル名とアップロード完了を確認してから共通送信へ戻る。送信後も利用者メッセージ側の添付を確認する。

時間を置いたタブなどで操作が反応せず、再読込後もchooserがタイムアウトする場合は、未送信本文・添付の有無を確認する。そのうえで同じ会話URLを新しいIABタブで開き、待機登録とクリックをやり直す。既存タブの状態を失わずに復旧できる場合がある。新しい会話への送信や二重送信はしない。

## 3. 受領ZIPを確認する

専用の受領ディレクトリで内容一覧と展開サイズを確認する。絶対パス、`..`、リンクによる範囲外書込を拒否してから展開し、製品ツリーへ直接展開しない。

生成コード・コマンドは内容を読んでから、許可された検証環境で必要な範囲だけ実行する。取得・展開と、製品への採用は分ける。

## 4. IABで保存先を確認できない場合

IABのファイルカードで`waitForEvent("download")`がタイムアウトしても、リンク表示だけでは取得済みにしない。まず同じ会話のカードをIABで再試行する。それでも保存先を確認できない場合に限り、同じログイン状態を確認できる通常Chromeのブラウザセッションで会話URLを開き直し、最新の再添付カードを選ぶ。

この例外は返却成果物の取得だけに使う。Cookieの抽出・移植、署名URLへの直接アクセス、raw API呼び出しは行わない。

通常Chromeで保存できた場合は、ダウンロード先の絶対パス、ファイルサイズ、SHA-256、`unzip -t`、manifestに列挙されたファイルのサイズ・SHA-256を確認する。検証済みZIPだけを専用の受領ディレクトリへコピーし、取得方法と検証結果を送信記録へ残す。
