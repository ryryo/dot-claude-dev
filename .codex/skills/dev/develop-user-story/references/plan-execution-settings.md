# PLANの推奨実行設定

PLANの新規作成・実行責務の意味変更時に読む。推奨設定は実行開始時の助言であり、製品契約、権限、Gate、検証水準を変えない。モデルや推論設定を自動で切り替えない。

## 1. PLAN冒頭へ記録する

タイトル直下へ4項目を置く。例の値を全PLANへ複製せず、その実行環境で選べる正確なmodel IDと対応する推論レベルを使う。

```markdown
- 推奨モデル: `gpt-6-astra`
- 推奨推論レベル: `high`
- 選定理由: 共有状態と失敗復旧の設計判断を、複数の利用側まで検証するため。
- 設定見直し条件: PLAN分割で統合責務がなくなる、またはこのmodel／推論レベルが選べなくなる場合。
```

`latest`、`flagship`、`高め`のような可変aliasや曖昧な値だけを書かない。利用可能性は実行環境のmodel一覧・tool定義・設定を確認し、不明な仕様はOpenAI公式資料で補う。APIの対応値をCodexの選択肢と同一視せず、そのhostが公開するmodelと推論レベルの組を確認する。

## 2. mainと委譲先を選ぶ

通常のmainはAstraを開始点とし、利用者が選んだSolや適用先で合意済みの運用を尊重する。名前を一括置換して既存PLANを移行しない。model選択の変更と、作業契約の変更は区別する。

| 実行主体 | 選定時の扱い |
| --- | --- |
| `gpt-6-astra` | 複数段階の判断・実装・検証を主導する通常のmain候補。現在の環境で利用可能か確認する |
| `gpt-5.6-sol` | 利用者指定、既存の合意、または代表作業の結果から選ぶmain候補。Astraと同じ製品・権限・Gate契約を担う |
| `gpt-5.6-terra` | 契約が固定され、局所判断と再現可能な検証で完了する作業の候補。可用性と採用理由を確認する |
| `gpt-5.6-luna` | 完全固定済み、独立または依存完了済み、排他的scope、localで可逆、強いoracle、分担利益がある機械的leafだけの候補 |

この表は運用上の担当基準であり、品質や費用の優位を保証しない。Lunaへsubagent委譲するときは[codex-luna-task-split](../../codex-luna-task-split/SKILL.md)または[codex-luna-sprint](../../codex-luna-sprint/SKILL.md)とworker自身の制約を満たす。`luna_sprint_worker`のmodel／reasoningは推奨表で上書きしない。

進行PLAN、candidate、integration、external PLANは各fileの責務を評価する。全laneの最も高い設定を一律に複製しない。

## 3. 推論レベルを選ぶ

既存の有効な設定や利用者指定を尊重する。新規PLANで指定も実績もない場合は、対応していれば`medium`を運用上の開始点にする。次の判断負荷と検証費用から必要な場合だけ調整する。

- `low`: 判断がほぼ固定済みで、局所変更と強いoracleにより確認できる。
- `medium`: 通常の複数step実装で、契約・scope・停止条件が明確である。
- `high`／`xhigh`: 複数component、非自明な状態遷移、再利用判断、分離、共有・外部状態など、実際に到達する難しい判断がある。
- `max`や環境固有のさらに高い値: 対応が確認でき、代表的な同種作業で追加推論の利益を説明できる場合だけ選ぶ。根拠なく最上位へ固定しない。

これらは対応値一覧ではない。実行環境が記載したmodelについて許可する値だけを使う。PLAN実行の推奨値に`none`は使わない。長さ、条件数、file数、最難関の仮想ケースだけで設定を上げない。未承認の外部作用や未確定の製品判断は、推論レベルで突破せず既存の停止Gateを守る。

## 4. 見直しと根拠

選定理由は、そのPLANに残る判断、失敗時の影響、oracleへ結び付ける。設定見直し条件は、統合責務の追加、利用者分離・外部作用への到達経路の追加、選定時の前提の反証、leafへの分割、model可用性の変更など具体的に書く。

設定だけの変更はPLAN独立レビューGateを失効させない。scope、risk、role、実装・検証責務を変える場合は[入口のGate再開規則](../SKILL.md#gateの再開と状態)に従う。推奨より低い設定で実行してもGateを弱めず、契約を完遂できない場合は未確認を明示して停止する。

公式仕様と、この文書の運用上の選定基準を区別する。[GPT-6 Astraのモデルガイド](https://developers.openai.com/api/docs/guides/latest-model)は、移行時に既存の有効な推論設定を保つこと、指示の監査、変更に応じた検証を案内している。この文書の担当表や新規PLANの開始値は、それ自体が公式の品質保証ではない。modelの仕様を根拠に変更する場合は公式資料と現在の実行環境を再確認する。
