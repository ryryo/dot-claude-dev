# レイヤー素材の設計と受け渡し

素材を作る前に読み、以下を対象画面に必要な分だけ記録する。特定フレームワークや今回のタロット専用パスを共通仕様にはしない。

## 素材表

既存のデザイン資料へ次の列を追加する。実装で参照する数が多い場合は同じ情報をmanifest JSONにしてもよい。説明とmanifestに同じ値を手作業で二重管理しない。

| 項目 | 記録する内容 |
| --- | --- |
| ID・役割 | 背景、人物、文字、飾りなど。主要コンテンツか装飾か |
| 採用元 | 参照画像と採用箇所。既存素材を再利用する場合はそのパス |
| 原本・配信先 | 編集用原本、最適化したファイル、アプリからのURL |
| 寸法・形式 | 実測ピクセル寸法、容量、PNG/WebP/AVIF/SVG等 |
| 透過 | 必要／不要、実際に確認したアルファ。背景付き素材に透過を要求しない |
| 描画範囲 | 大きな透明余白がある場合の内容の外接矩形と、その測定基準 |
| 表示方法 | contain/cover、基準位置、切れてよい範囲、反転の可否、重ね順 |
| 対応幅 | PC・スマホでの表示幅や上限、専用素材が必要ならその理由 |
| 代替テキスト | 意味のある画像の読み上げ文、または装飾であること |

## 作り方の判断

- 素材化する前に既存の原画・透過データ・SVGを探す。カンプから切り抜くより正本の再利用が適切なら、再生成しない。
- カンプ内で隠れている部分を別配置で露出させる場合、切り抜きだけでは絵が足りない。必要な範囲を生成・編集して補い、同一性を確認する。
- 人物やキャラクターをパネルへ重ねるなら、接点と前後関係を決める。前足や手が切れる、本文へ被さる、透明余白のせいで浮く、といった不整合を組み合わせて確認する。
- 複数枚のカード、商品などを別々に配置するなら、各素材に分ける。番号やラベルはHTMLで重ねる。
- 左右反転を使う前に、文字や左右非対称の意味がないか確認する。反転可能な雲などは同じ素材を再利用できる。

## 透過・描画範囲の確認

1. ファイルの実形式・寸法・アルファの有無を調べる。アルファチャンネルがあっても全画素不透明なら、透過素材とは扱わない。
2. 明色・暗色と想定背景で画像を実際に表示し、疑似的な市松模様、白い縁、穴、切断、残った背景を確認する。
3. エッジに問題があれば、利用中の画像編集ツールの規則に従って修正する。透過を宣言するだけ、CSSのブレンドだけで問題を隠す、全画像への一律な色抜きでは済ませない。
4. 原寸画像と必要な配信解像度を残す。端末の画素密度と最大表示幅に合わせ、文字や細い線が崩れない符号化を選ぶ。

透明余白は不要と決めつけて削らない。安全余白が必要な絵は保持し、描画範囲の情報を使って配置する。CSSのラッパー、適切な画像書き出し、インラインSVGのviewBox等から選び、元画像の縦横比を保つ。

インラインSVG内の `<image>` を使う場合は、viewBoxだけでなく参照画像の実寸も指定する。外部画像を参照するSVGをさらに `<img>` として読み込むと、ブラウザの制約で内部の画像が表示されない場合があるため、実際の読み込み方で確認する。

## 組み合わせプレビュー

- ページ全体の画像ではなく、配信予定の素材とHTML/CSSを使う。背景・人物・文字・操作部品を実装と同じ前後関係で配置する。
- レイヤー切替や背景切替は、透過・重なりを確認する必要がある場合にだけ追加する。
- 元カンプのキャンバスサイズを固定したまま縮小せず、コンテナ幅を変え、自然な高さ・改行・スクロールで確認する。
- 単体素材は良好でも組み合わせるとサイズやタッチが合わないことがある。ユーザーが主要操作へ自然に目を向けられる濃淡と密度かを確認する。

## 受け渡しの完了条件

- 採用版と候補が区別され、アプリが参照する素材はリポジトリ内に揃っている。OS一時領域や生成ツールの保存先だけに依存しない。
- 生成した素材は `imagegen-core` の採用・プロンプト・レビュー記録にたどれる。簡単なSVGやCSSはソース自体を正本にできる。
- 原本と配信用素材、組み合わせ例、配置上の注意が揃う。素材のみなら、本体への組み込みや操作は未実装と明記する。
- 実装まで行った場合は、プレビューの出来だけで完了にせず、アプリの読み込み・操作・レスポンシブ表示も検証する。
