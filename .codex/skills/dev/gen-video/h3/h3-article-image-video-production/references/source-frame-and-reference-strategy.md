# 素材・フレーム・参照設計

## 既存素材から先に探す

新規生成の前に、記事、Lab、関連ページ、商品資料から次を棚卸しする。

- 現在の対象画像と原寸
- 同じ人物・商品・場面の別カット
- 既存動画と切り出し可能な有効区間
- 承認済みの商品画像、人物画像、様式見本
- 過去候補のうち、全体は不採用でも一部が使える素材
- 文字入り・文字なし、縦・横、寄り・引きの違い

素材の出所と役割を記録する。似ているだけの非承認商品を形状参照にしない。

## 不足を分類する

追加画像は「あると良さそう」ではなく、次の不足を解決するときだけ作る。

| 不足 | 診断 | 典型的な補完 |
|---|---|---|
| 状態 | 必要な開始・途中・終了がない | 必要状態だけ抽出・生成 |
| 構図 | 向き、角度、余白、画角が動作や文字に合わない | クロップ、編集、別構図画像 |
| 同一性 | 人物や商品を固定する根拠が弱い | 承認済み参照の追加 |
| 形状 | 層、継ぎ目、厚み、接点が不明 | 単純背景の商品状態、構造ラフ |
| 追従基準 | 効果を固定する身体部位や境界が見えない | 基準点が明確な向き・画角 |
| 連続性 | 場面間で人物、部屋、商品が飛ぶ | 中間状態または権限を絞った終端 |
| 品質 | 解像度不足、破綻、不要文字がある | 原本探索、クリーン化、文字なし版 |
| 様式 | 実写感、図解、グラフィック様式を定義できない | 様式専用参照 |

## 最小補完の順序

不足があっても、全体の新規生成から始めない。

1. 既存動画から有効区間またはフレームを抽出する
2. 既存画像をクロップ、軽微編集、文字除去して使う
3. 構造ラフや単純背景で成立条件を検証する
4. 不足している開始・終了・中間状態だけを生成する
5. 元素材では目的を制御できない場合のみ全体を新規生成する

各追加素材に次を付ける。

```markdown
- source_id:
- resolves_gap:
- authority:
- must_preserve:
- must_not_transfer:
- acceptance:
```

`resolves_gap` が空の追加画像は作らない。

## 商品・物理動作の契約

商品の形状や持ち方が意味に直結する場合は、人物や室内を加える前に商品契約を作る。

- 部品・パネル・層の数
- 開いた状態、畳んだ状態、積層状態
- 厚み、縁、縫製、ファスナー、継ぎ目
- 床、手、身体との接点
- 回転軸、支持点、重心、移動方向
- 途中で変わってよい部分と固定部分

「折り畳む」と「畳まれた物を持ち上げる」のような別動作を混同しない。重い物体を上へ飛ばすなど、演出のために物理を逆転させない。複雑な形状は、承認商品参照を実際のImageGenまたはH3入力に含め、単純背景で状態を先に検証する。

決定論的な3Dや合成工程を自動的に増やさない。promptと参照設計で十分かを先に判断し、それで制御不能な場合だけ制作方法を拡張する。

## 参照権限マップ

参照を「全部真似する画像」と扱わない。参照ごとに権限を分ける。

| 権限 | 例 |
|---|---|
| identity | 顔、髪、体型、人物の一貫性 |
| product | 形状、色、縫製、層数、ロゴ |
| composition | 人物・商品・余白の配置 |
| start_state | 開始姿勢、開始商品状態 |
| end_state | 終了姿勢、終了商品状態 |
| environment | 部屋、家具、光、生活感 |
| visual_style | 実写感、図解、コラージュ、字体 |
| motion_editing | 動作、転換、リズム。静止画から推測させすぎない |

同時に `must_not_transfer` を指定する。たとえば、終了姿勢だけを使いたい参照から、別の部屋、服、商品形状まで転写させない。強い終了参照で画面全体が別物になる場合は、参照を増やすのではなく権限を狭める、終端画像を作り直す、またはモードを再選択する。

## H3モード選択

- **I2VA**: 一枚の承認画像が人物、商品、構図を十分に固定し、必要なのが自然な局所動作である。
- **FL2VA**: 開始と終了の状態差が重要で、両端を明示しないと結果がぶれる。
- **Ref2VA**: 人物、商品、様式、既存動画など複数の異なる権限を参照させる。
- **T2VA**: 固有人物・商品への忠実度が不要な概念挿入で、テキストだけで十分に制御できる。
- **L2VA**: 対応環境で利用し、既存latentまたは継続素材を使う明確な理由がある場合だけ候補にする。詳細はH3専門スキルに従う。

モード名から企画を決めない。Article Video Brief、必要状態、参照権限を先に確定し、その実装としてモードを選ぶ。

## 文字・効果の制作主体

次はH3内生成の候補になる。

- 動作や場面転換とタイミングが一体
- 人物や商品へ追従する
- 文字自体が変形・退出・出現する
- ユーザーがH3内での生成を明示している

次はHTML/CSSまたは後編集の候補になる。

- 長い説明や注意書き
- レスポンシブ、アクセシビリティ、差し替えやすさが重要
- 動画と独立した静的補足

ただし、ユーザーが制作主体を指定した場合はそれを固定条件にする。生成失敗を理由に、無断でH3内文字をHTMLへ移したり、要求された効果を削除したりしない。
