# 抽出画像を実際に分析する

この手順はCodexまたは指定された画像対応モデルが行う。CLIの数値出力を読むだけでは完了しない。

## 代表画像

prepareが返した画像を時刻順に閲覧し、まず以下を把握する。

- 主要な人物・物体と位置関係、画面内の大きさ、カメラの向き
- 各画像で観察できる形状、姿勢、接触、遮蔽、存在状態
- 指定された動作の前・途中・結果のどれが見えているか
- 期待する構図や固定要素との具体的な不一致の候補

プロンプトに書かれていることを「画像でも見えた」と補完しない。見えない手、物体の裏側、画面外の状態は不明。別ショットの人物を服の色だけで同一人物と確定しない。

## 追加方法を決める

| 疑い | 取得方法と見る内容 |
| --- | --- |
| 手や物体の形が変わった、接地がおかしい | sequenceで短区間の前後を取り、同じ部位と接触点を追う。編集点、遮蔽、ブラーと区別する |
| 主動作が完了していない | lateで後半状態を確認。動作の過程が必要ならsequenceを使う |
| 場面やカメラが要求から外れた | 代表とnoveltyで構図を比較。動くカメラを指定しているなら移動自体を不良としない |
| 必要な文言が途中までしか見えない | lateで完成状態を確認。読ませる文字だけを扱う |
| 疑問は出なかったが未確認候補が多い | supplementで少数補完。新情報、同じ意味の別姿勢、読めない画像を区別する |

近接画像列は時刻順に読み、対象が同じショット内にあるかを確認する。「消えた」は画面外や遮蔽の可能性、「浮いた」は走行の遊脚期や演出の可能性を検討する。先に成功・失敗を決めて根拠を探さない。

画像を見た後は、観察したことと推論を分け、判断を変える証拠が得られたかを確認する。疑いが解消した画像は修正指摘に残さない。新しい意味のない画像を何枚も読み続けない。

## 分担する場合

ユーザー指定や実行環境の契約で分担できる場合だけ、対象画像と次の情報を渡す。

- 元プロンプトから今回確認する必須条件と、参照素材の責務
- 画像パス、時刻、数値segment ID
- 既に見えたこと、未確認の疑い、残り追加予算
- 出力は観察事実・根拠時刻・追加が必要な疑問。意味が不明なら断定しない

元動画や全候補を無条件に読み直させず、渡した画像を実際に閲覧させる。補完確認には既存の読取結果を引き継いでよい。独立した精度測定を依頼された場合だけ、正解や以前の評価結果を伏せる。
